# Command-line interface contract

These tests cover `sva2yosys.cli` (the `sva2yosys` console script and `python -m sva2yosys`). The usage is described in the module docstring of `src/sva2yosys/cli.py` and, for users, in `docs/usage.md`.

Positional arguments are the verification files; the design is found with `-y`/`--libext`/`-v`/`-f`/`-F`. Without `-o` the command checks; with `-o DIR` it also writes the rewrite (`sva2yosys.rewrite`).

## Fixtures

- `fixtures/accepted.sv`: two supported assertions (one unlabelled) and an assume.
- `fixtures/mixed.sv`: one supported assertion and two unsupported ones (a strong unbounded `assume`, whose liveness is not supported, and a multiclock property).
- `fixtures/broken.sv`: a source that Slang does not compile.
- The `counter` design (`design/`, used as a `-y` directory) and properties of `tests/functional_tests/rewrite/fixtures`, for generation.
- `fixtures/preproc/verify`: counter properties whose assertion is enabled by `-D WITH_STEPS` and whose glue comes from a relative include (`glue.svh`).
- Small designs written into `tmp_path` for library search, filelists and packages.

## Contract

1. **Entry points.**
   - The installed `sva2yosys` console script resolves to `sva2yosys.cli:main`.
   - `python -m sva2yosys --help` prints the usage and exits with 0.
2. **Accepted design.** Every assertion is reported on an `ok` line with its scope, name, kind, slot count, form and temporal bits; an unlabelled one is named `(unnamed)`. The summary says how many were accepted, and the exit status is 0.
2a. **Per-attempt machines.** A directive compiled to the per-attempt machine is reported with `slots=0`, `form=attempt` and its register count as `bits` (e.g. `a |-> (b |-> c)`), whatever `--strategy` says. A `cover` that the cover rule rejects (`docs/semantics.md` §9.5) is reported on a `rejected` line at the directive, with the cover-rule message.
3. **Rejections.** Each unsupported assertion is reported on a `rejected` line with the source position of the offending construct and the converter's message. Supported assertions in the same design are still reported as `ok`. The exit status is 1.
4. **Compile errors.** For sources that do not compile, Slang's report is written to standard error and the exit status is 1.
5. **Options.** `--top` selects the top module, `-D` defines a macro, and `-I` adds an include directory, all as for Slang.
6. **Usage errors.** No verification file, a design (`-y`, `-v`, `-f`, `-F`) without `--top`, or `--equivalence` without `-o`, gives exit status 2.
   SVA left in a design file is an error in generation unless `--allow-design-sva` is given; then it is a warning (`rewrite`, point 6 of its contract).
7. **Generation.** With `-o DIR`, the command writes into `DIR`, creating it if needed:
   - the rewritten verification files and the design copies, under their base names, with the texts of `rewrite` for the same loaded sources;
   - `sva2yosys_monitors.sv`;
   - `sva2yosys_read.ys`: one `read_verilog -formal -sv <-D…> <-I…> <file>` per file to read, in the order of `sva2yosys.f`, all with absolute paths.
     - Every command carries the `-D` definitions (`-DNAME=VALUE`) and the `-I` directories. A written file first gets the directory of its original, so its relative includes resolve as they did for Slang.
     - Under SBY (`script sva2yosys_read.ys`), the `preproc` fixture then proves against the correct counter and fails at step 8 against the mutant. That shows the `-D`-enabled assertion and the included glue are both present.
   - `sva2yosys.f`: the files to read, one per line: `sva2yosys_monitors.sv`, then every input such that a file declaring a package precedes every file using it (`import p::…`, `p::x`, transitively), and otherwise design files precede verification files, each in loading order. A written file is listed by its name relative to `DIR`; an untouched one by its absolute path.

   Written files are UTF-8 with `\n` line ends. Each is written through an exclusively created temporary file in `DIR`, so no existing file other than the destination is ever touched.

   It prints one `wrote <path>` line per file, then warnings, and exits with 0.
8. **Generation errors.** Every diagnostic is written to standard error, nothing is written, and the exit status is 1, when:
   - the rewrite is refused;
   - package dependencies between files form a cycle;
   - an include of a written file would find another file in `DIR` (a file named like the include, already there or written now);
   - a path, definition or include directory contains whitespace;
   - a written file would replace an input file (e.g. `-o` names the directory of an input), or two written files would share a name (e.g. a verification file named `sva2yosys.f`).
9. **Finding the design.**
   - `-y DIR` loads exactly the needed files: the targets of binds, the `--top` modules and, transitively, what they instantiate or import. Other files in `DIR` are not loaded or listed (`sva2yosys.slang.invoke.load_design`).
   - A `--top` module is looked up in the design even when a verification file declares the same name; a module, interface, program or package declared in two loaded files is an error (exit status 1).
   - `-v FILE` loads a file.
   - `-f`/`-F` read a filelist (`sva2yosys.filelist`): its files, `-y`, `+define+` … are used as on the command line, and an unknown filelist option is an error (exit status 1).
11. **Unbounded antecedents**. `a ##[1:$] b |-> ##[1:8] c`, `a[*1:$] ##1 b |=> c` (an `assume`), `b[->2] |-> c` and `always (a |-> b)` are reported `ok` with `form=direct`, whatever `--strategy` says (the optimised forms do not apply to a loop in the antecedent); a `cover` of an unbounded antecedent and `a |-> ##[1:$] b` are `rejected` at their position with "unbounded ranges ($) are not supported yet".
10. **Monitor forms.**
    - `--strategy direct` is the default: every monitor is direct and every check line says `form=direct`.
    - `--strategy auto` picks `window` where it applies and `direct` needs at least `3 x window + 4` state bits (`optimize.forms.choose`), e.g. for `a |-> ##[1:16] b` (6 bits), and `direct` elsewhere, also for `a |-> ##[1:4] b ##[1:4] c`; it never picks `history`. `--strategy history` forces `history` wherever it applies. The check line reports the chosen form and its bits; every generated monitor's header names its form.
    - With `--equivalence`, `DIR/equivalence/<monitor>/` holds the equivalence job of each optimised monitor (under `auto` and under `history`), and each job proves under SBY.

12. **Weak unbounded consequents**. `a |-> ##[1:$] b`, `a |-> b[*1:$] ##1 c`, `a |=> b[->2]` and `always (a |-> b[*1:$] ##1 c)` (assert/assume) are reported `ok` with `form=configurations` and `bits` the number of configurations plus the antecedent bits, whatever `--strategy` says; a consequent that can never fail is warned about (point 16). `not` of an unbounded sequence and every `cover` with an unbounded part not covered by points 14 and 17 are still `rejected` with their messages. `a |-> ##[1:$] 1'b0` is `ok` (a constant-false condition is evaluated at its own sample, so it never fails, `docs/semantics.md` §3). A property over the configurations budget is `rejected` with a located message.

13. **Weak `until` / `until_with`**. `assert property (a |-> b until c)`, `assume property (a |=> b until_with c)`, `assert property (b until c)` and `assert property (always (a |-> b until c))` are reported `ok` with `form=configurations`, whatever `--strategy` says. `s_until`, `s_until_with`, `not (b until c)` and `cover property (b until c)` are `rejected` at their position with a message naming `until`.
14. **Covers of unbounded sequences**. `cover property (a ##[1:$] b)`, `cover property (b[->2])`, `cover property (a |-> ##[1:$] b)` and `cover property (a |=> b[*1:$] ##1 c)` are reported `ok` with `form=configurations` and `cover`, whatever `--strategy` says. An explicit `weak(...)` of an unbounded sequence, a weak `until`/`until_with`, an unbounded or multi-length antecedent with an unbounded consequent, and every other cover with an unbounded part are `rejected`, located, with the messages of `docs/usage.md`.

15. **X-checks** (`docs/semantics.md` §8a; `fixtures/xchecks.sv`). `$isunknown` is evaluated as 0 (the model is two-state).
    - A directive that checks nothing afterwards (`assert property (!$isunknown(s))`, `v |-> !$isunknown(s)`, an `assume` of it, a `cover` of `$isunknown(s)`, a trigger `$isunknown(s) |-> p`) is reported on a `skipped` line, `skipped   <file>:<line>:<col>  <scope>.<name>: X-check: <reason>`, at the directive, in source order with the other lines. It is not an error: the exit status stays 0 when nothing is rejected.
    - A directive that keeps other checks (`a |-> b && !$isunknown(c)`) is `ok` as usual and is followed by a line `warning   <file>:<line>:<col>  <scope>.<name>: <message>`, located at the first `$isunknown`, saying that the X part was dropped and that the rest is still checked. A rejected directive prints no warning.
    - The summary counts the skipped ones apart: `N assertion(s): A accepted, S skipped (X-check), R rejected`; the `S skipped (X-check),` part appears only when `S > 0`, so a run without X-checks prints the summary of before.
    - `--x-checks=reject` (default `skip`) rejects every directive using `$isunknown` on a `rejected` line at the call, exit status 1, and prints no `skipped` or `warning` line. `$isunknown` of a `$past` operand is rejected under both, located at the call.
    - With `-o`, the skipped directive is removed from the rewritten file (`rewrite` contract, point 9); the command prints a `note: skipped (X-check)` line per skipped site and the warnings of kept directives, and its last line ends with `, S skipped X-check(s)` when `S > 0`. The monitors file has no monitor for it.

16. **Consequents that can never fail** (`docs/semantics.md` §9.1, §9.6; `fixtures/never_fails.sv`). An `assert` or `assume` that is accepted with a configuration-set part (`form=configurations`) that provably cannot fail (`temporal.configurations.never_fails`: `a |-> ##[1:$] b`, `a |-> ##[1:$] b ##1 c`, `a |-> ##[1:$] 1'b0`, `a |=> ##[1:$] b`, `always ##[1:$] b`, `##[1:$] b`) is `ok` as usual (same `ok` line, same summary counts and exit status, monitor unchanged) and is followed by a line `warning   <file>:<line>:<col>  <scope>.<name>: <message>`, located at the directive (the same position as its `ok` line), after the `ok` line.
    - `assert`: `this assert can never fail: its weak unbounded consequent always keeps a live match (a liveness check needs strong(...) or s_eventually, see docs/usage.md)`; for a sequence as the whole property `its weak unbounded sequence`. `assume`: `this assume can never fail, so it constrains nothing: its weak unbounded consequent always keeps a live match (a fairness constraint needs a strong assume, see docs/usage.md)`.
    - A top-level `and` is checked per conjunct: only the conjunct that cannot fail is warned about, and the message names it (`conjunct 2 of 2 of this assert can never fail: ...`).
    - A discharge by matching is not a failure: `a |-> b[*1:$]`, `a |-> b[*1:$] ##1 c`, `b until c` and `a |-> b ##1 (c ##[1:$] d)` get no warning, nor does a `cover` or a bounded assertion. A rejected directive prints no warning.
    - With `-o`, the same warning is written as `<file>:<line>:<col>: warning: <scope>.<name>: <message>` after the files, counted in `N warning(s)`, once per site and message.
17. **Strong liveness** (`docs/usage.md`). `assert property (a |-> s_eventually b)`, `s_eventually [2:$] b`, `a s_until b`, `strong(a ##[1:$] b)` and the other strong unbounded forms of `docs/supported-sva.md` are `ok` with `form=configurations`. The `ok` line of a directive with a liveness part ends with `live=pending` (one configuration) or `live=witness` (several); the parts of a property `and` that have one are joined with `+`; a directive without one has no `live=` field. A strong unbounded `assume` is `ok` with `live=pending` when it has one configuration and `rejected` with the liveness message otherwise (point 19). With `-o`, `sva2yosys_read_live.ys` is written next to `sva2yosys_read.ys` when some directive has a liveness part, and only then: the same commands with `-DSVA2YOSYS_LIVE` on every `read_verilog` line (after the other `-D` definitions). The `wrote` lines list it. A `prove` task reading `sva2yosys_read.ys` sees the monitors without any liveness logic.
18. **`not` of an unbounded sequence** (`docs/usage.md`). `assert property (not (a ##[1:$] b))`, `not weak(...)`, `not (a until b)` and `c |-> not (a ##[1:$] b)` are `ok` with `form=configurations` and `live=pending` (one configuration) or `live=witness`. `not strong(...)`, `not (a s_until b)` and `not s_eventually b` are `ok` with no `live=` field, also as an `assume`. `assume property (not (a ##[1:$] b))` (a strong assumption needing a witness) is `rejected` with the liveness message; any `cover` of a `not` with an unbounded part stays `rejected`. `sva2yosys_read_live.ys` is written exactly when some accepted directive has a liveness part, so for `not (a until b)` and not for `not strong(a ##[1:$] b)`. (`assume property (not (a until b))` is accepted with `live=pending`, point 19.)
19. **Strong `assume` in the one-configuration class** (`docs/usage.md`). `assume property (a |-> s_eventually b)`, `s_eventually b`, `a |-> b s_until c` and `not (a until b)` are `ok` with `live=pending` (the assume's fairness constraint), and `sva2yosys_read_live.ys` is written. An `assume` needing a witness (`a |-> strong(##[1:$] b)`, `not (a ##[1:$] b)`) is `rejected`, located at the directive, with a message containing `a strong unbounded property (liveness) in 'assume'` and the word `witness` (it says why). Amends points 17 and 18: they no longer say that every strong `assume` is rejected.
    - **Cover warning.** When a run accepts an `assume` with a liveness part, each accepted `cover` is followed (right after its `ok` line, located at the cover, like the never-fails warning) by `warning   <file>:<line>:<col>  <scope>.<name>: this cover's result ignores the fairness assumptions (strong assume) of this run: a reached cover is provisional, see docs/usage.md`; it does not depend on the order of the directives; no assert, assume or rejected cover gets one; the exit status and the summary counts are unchanged. A run with no such assume (a strong `assert`, a weak or `not strong` assume) prints none. With `-o` it is written and counted like the other warnings.
    - **Never-fails hint.** The warning of point 16 for an `assume` ends with `(a fairness constraint needs a strong assume, see docs/usage.md)`.


20. **Resource exhaustion.** A huge bounded canonical property is rejected promptly, with the directive's source location and exhausted resource, for assert/assume/cover and regardless of strategy. Output mode and check mode share the guard; exhausted output mode leaves no newly written output.

**Scheduling.** The small auto/window equivalence-job proof remains in default; the multi-job history parameter uses `--extended` or `--slow`. Quick CLI diagnostics and output checks remain in default. The proof matrix and its assertions are unchanged.

21. **Default sampled values** (`docs/semantics.md` section 8). A sampled-value call whose operand is not all X before the first clock tick (a 2-state or initialised signal, a constant bit in the operand) is a `rejected  <file>:<line>:<col>  <scope>.<name>: ...` line, exit status 1, with the message "before the first clock tick is not unknown" and the remark that a "disable iff" does not help; the same call over an input port of 4-state type is `ok`.

22. **Version**. `sva2yosys --version` prints `sva2yosys <version>` on standard output and exits with status 0, without reading any file. `<version>` is the version of the installed package, which is the `version` of `pyproject.toml`: the one place a release number is written. It has the form `MAJOR.MINOR.PATCH` (semantic versioning; below 1.0.0 a minor bump may change the command line, the shape of the generated monitors or the accepted subset, a patch bump only fixes defects), and the `sva2yosys` entry of `uv.lock` records the same number. Generated files carry no version, so a release never changes an output.

23. **The Yosys frontend** (`docs/usage.md`, *Binds and the Yosys frontend*). `--yosys-frontend verilog|slang` selects the frontend that the written read script uses; the default is `verilog`, and with it every output is byte-identical to the one without the option.
    - **`slang`, check mode.** A directive with a liveness part (a strong unbounded `assert`, or a strong `assume` read as a fairness constraint; the `live=` field of an `ok` line) is `rejected` at its location, with a message that names `--yosys-frontend slang`, says that `read_slang` does not support the strong forms, and points to the default frontend. A directive without a liveness part is `ok` as before, and so is a `cover`. The rejection counts in the summary and in the exit status like any other.
    - **`slang`, generation (`-o`).** The same directives are refused by the rewrite with the same message (it is one rule, `passes/frontend.py`, used by both), and nothing is written. `--top` is required (usage error, status 2): without it `read_slang` would also elaborate the bound property module as a top of its own, on free inputs. The option needs no design file.
    - **The files.** `sva2yosys_read.ys` is `plugin -i slang` followed by one `read_slang --best-effort-hierarchy --allow-use-before-declare -D FORMAL` command (a monitor declares its sampled-value history registers after the conditions that read them, which Slang refuses by default) with the `-D` macros, one `-I` per include directory (and per written verification file, its original directory), one `--top` per `--top`, then the monitors file and the inputs in reading order (a written file under its output name, a design file where it is). There is no `sva2yosys_read_live.ys`. `sva2yosys.f` is as before. `--equivalence` is unchanged.
    - **Behaviour.** The default and `slang` flows give the same prove and cover verdicts, and name the failing assertions by the same instance paths (checked with SBY, points 5 to 7 of `formal_designs`).

24. **One live script per liveness part** (`docs/usage.md`, *Strong properties*). SBY's `live` mode decides a task by the first justice verdict (SBY issue 378), so with `-o` every liveness part of an `assert` (a monitor with a liveness block; a property `and` has one per part, named `p<N>_c<k>`) gets `sva2yosys_read_live_<part>.ys`: the commands of `sva2yosys_read.ys` with `-DSVA2YOSYS_LIVE_<part>`, and `-DSVA2YOSYS_LIVE_FAIR` exactly when the design has a fairness `assume`, after the user's defines. They are written (and announced as `wrote ...`) even for a single part, and not at all without a liveness part or with `--yosys-frontend slang`. `sva2yosys_read_live.ys` (every part at once) is unchanged. When a design has more than one liveness part, each part gets a warning at its directive that one `live` task reports only the first verdict and names the script to use (check mode says the same without the script name, so both modes warn alike); with one part there is none. A monitor shared by several elaborated instances counts once for each instance, and its warning says that no define separates the instances.
