# Reference semantics contract (Layer 1: normative trace tables)

These tests pin down the meaning of the supported constructs on hand-written traces. The reference evaluator (`support.reference.evaluate`, in `tests/support/reference`) must reproduce every table exactly. The same tables will later be run through the temporal machine (Layer 2) and the generated monitors (Layer 3). The rules are those of [`docs/semantics.md`](../../../docs/semantics.md); the table format is described in `tests/support/tracefile.py`.

The expected rows were derived by hand from the semantics, not from the implementation. If the evaluator and a table disagree, the case is analysed by hand before either one is changed.

The discharge-mutant case in `counterexamples.trace` pins a sole trigger at
sample zero and its window match at sample one: it succeeds at one, never fails
later, and leaves no pending attempt. The table cites its IEEE clauses and origin.

## Case metadata

Every case of every table states what grounds its expected rows (`tests/support/tracefile.py`, enforced by the parser and by `test_trace_metadata.py`):

- `clause:` the IEEE 1800 clauses that decide the verdict: space- or comma-separated items, each `16.9.2` style (digits and dots) or `Annex F`. Required.
- `class:` required, one of `normative` (the standard decides the verdict), `interpretation I<n>[, I<m>...]` (the verdict depends on the listed interpretations of `docs/validation.md` section 5), `implementation-defined` (it rests on a choice the standard leaves open, such as the two-state model) or `must-reject` (an illegal property; it needs `support: oracle`).
- `origin:` where the case came from. Optional, except in `counterexamples.trace`, where every case has one.

Every interpretation id of a case is a row id of `docs/validation.md` section 5, and an `interpretation` class always names at least one id.

## Traceability page

`docs/traceability.md` is generated from the trace cases (`tests/support/traceability.py`; its docstring is the contract of the generator) and enforced by `test_traceability_page.py`:

- the committed page equals the regenerated one (`uv run python tests/support/traceability.py --write` rewrites it);
- every construct of the generator's table has at least one accepted (not `support: oracle`) case;
- every row of the `docs/supported-sva.md` matrix whose status cell contains TESTED anywhere (DIFFERENTIAL TESTED, or a mixed status such as "CODEGEN IMPLEMENTED ... without arguments: TESTED") is mapped, either to a construct or to a structural row; every structural entry cites a numbered point of a `CONTRACT.md` that is checked to exist; and every mapped row exists in the matrix.

## Test matrix page

`docs/test-matrix.md` is generated from the collected test suite (`tests/support/suite_matrix.py`; its docstring is the contract of the generator) and enforced by `test_suite_matrix_page.py` (extended tier: it collects the whole suite): the committed page equals the regenerated one (`uv run python tests/support/suite_matrix.py --write` rewrites it; adding or removing a test changes its counts).

## How a case runs

1. The case's property is placed in a module by `sv_source`: `p: <kind> property (@(posedge clk) [disable iff (<disable>)] <property>);`. With `procedure: initial` the directive is placed in an `initial` block (`initial p: ...;`): the directive then has one evaluation attempt, at the first tick of its clock (IEEE 1800-2017 16.14.6; `docs/semantics.md` section 6), and the expected rows are those of that single attempt.
2. The module is compiled and exported with Slang, then converted. It must produce exactly one directive, with no rejection and no first-sample problem (`passes/first_sample.py`).
3. The trace gives each row signal `tc.<row>` its value at each sample. There are no values before sample 0: a condition containing `$past` does not hold at sample 0 (`docs/semantics.md` §8).
4. `evaluate(directive.property, trace, directive.disable)` must give:
   - `failures` = the `fail` row, for `assert` and `assume` cases. For `cover`, failures are not what the directive reports, so they are not compared.
   - `successes` = the `pass` row.
   - When `pending:` is given, the number of distinct obligation starts still pending at the end (excluding disabled ones) equals it.
5. When `final-fail:` is given, `finalize(directive.property, evaluation, cover)` reports that many distinct obligation starts failing at the end of the simulation: the pending obligations whose sequence is strong (`strong(...)`, or a plain sequence in a `cover`), never the weak ones (`docs/semantics.md` §9.1).

## Attempt scope and oracle-only cases

A case with `scope: attempt` is checked against the per-attempt oracle (`evaluate_attempts`, `attempt_results`, `finalize_attempts`; `docs/semantics.md` §9.2) instead of the obligation-level one. Every sample starts an attempt; its outcome is TRUE, FALSE, pending or disabled, with its nonvacuity (§16.14.8). The case must give:

- `outcome:` (optional) one token per start sample: `T`/`t` TRUE nonvacuous/vacuous, `F`/`f` FALSE nonvacuous/vacuous, `U`/`X` TRUE/FALSE with nonvacuity still unknown at the end of the trace, `p` pending, `d` disabled;
- `decided:` (optional) the decision (or disable) sample of every attempt, `.` while pending;
- `fail` = the decision samples of the FALSE attempts (`assert`/`assume` only; not compared for `cover`);
- `pass` = the decision samples of the TRUE attempts whose nonvacuity is true and known at or before the decision;
- `pending:` = the number of pending attempts at the end; `final-fail:` = the number of those that finalize FALSE (a pending sequence is TRUE if weak and FALSE if strong, `not` swaps, an implication combines its started consequents and ignores antecedent matches ending after the trace; `nexttime [n] p` whose `n`-th event lies beyond the trace is TRUE if weak and FALSE if strong (`s_nexttime`), else `p`'s finalized outcome; `always`/`eventually [m:n]` combine their started offsets as `and`/`or`, each missing offset counting TRUE for the weak forms and FALSE for `s_always`/`s_eventually`).

The temporal operators are evaluated natively, never by desugaring: `nexttime [n] p` is `p`'s attempt `n` events later; `always [m:n] p` is FALSE at the first FALSE offset and TRUE when every offset `m … n` has started and holds; `eventually [m:n] p` is dual. Their nonvacuity is offset-ordered (`docs/semantics.md` §9.2): `always` is nonvacuous when some offset's attempt is nonvacuous and every earlier offset holds, `eventually` when some offset's attempt is nonvacuous and no earlier offset holds; an offset not yet reached or still pending is unknown.

The reference evaluator evaluates natively, on finite traces, the unbounded and `until` constructs (all in attempt scope; `support: oracle` unless the pipeline supports the property: the unbounded antecedents and unbounded `always` over supported operands are supported, and run through the machine and the monitors). Unbounded `##[m:$]`, `[*m:$]`, `[->m:$]` and `[=m:$]` are matched by exploring every end that the known samples and the sequence's fixed lengths allow; `$` is never replaced by a bound, so an alive unbounded sequence is pending, never false. Goto `b[->m:n]` and nonconsecutive `b[=m:n]` repetition are matched from their definitions (§16.9.2) by counting the samples at which `b` (or `!b`) holds. `always [m:$] p` is FALSE at the first FALSE started offset and never TRUE online; `s_eventually [m:$] p` is TRUE at the first TRUE started offset and never FALSE online, with offset-ordered nonvacuity whose offsets after the known samples are unknown. `p until q` and the `s_`/`_with` variants (Boolean operands) are TRUE where `q` holds (`until_with`: where `p` and `q` hold), FALSE where `p` does not hold, else pending, nonvacuous from the start. At the end of a simulation, a pending weak form (`always`, `until`, `until_with`, a weak sequence) is TRUE and a pending strong form (`s_until`, `s_until_with`, `strong(...)`, and for `s_eventually` the offsets after the trace) is FALSE; `not` reverses this. Laws between the native nodes and their definitions are tested on every trace of up to three samples of two signals in the default run, and up to five in the slow run (`tests/unit_tests/test_reference_unbounded.py`).

**Lasso cases.** An attempt-scope case may declare `loop: k` (`0 <= k <` the number of written samples). The infinite trace is then the written samples `0 … k-1` followed by `k … last` repeated for ever; every other row keeps describing the written samples as a finite trace, so the finite semantics stay checked on the same data (the finite rows are compared as above). Two more rows, one token per written sample (the start of an attempt; the results of later starts repeat with the loop period), give the exact result on the infinite trace (`support/reference/lasso.py`, `lasso_attempt_results`):

- `inf-outcome:` `T` TRUE, `F` FALSE, `D` disabled. Never pending: on an infinite trace an attempt that no finite prefix decides is TRUE if weak and FALSE if strong (a sequence alive for ever without a match, `until`, `not` reversing it, `and`/`or`/implication combining their parts), and `always` / `eventually` / `nexttime` combine the operand at every offset, which all exist (so the weak and strong forms of a bounded property agree);
- `inf-decided:` the sample at which the attempt is decided online (the decision of the finite evaluator on any prefix that contains it), the first disable sample for `D` (the condition holds at a sample of `[start, decision]`, of `[start, ∞)` for an undecided attempt), and `.` when no finite prefix decides the attempt (the outcome holds only in the limit).

"Pending for ever" is concluded only from a structural argument (docstring of `lasso_attempt_results`): the sampled trace is periodic from `W = k + d` (`d` the largest sampled-value depth); the results of an attempt started at `p >= W` are those of the class `W + (p - W) mod L` shifted; for a sequence with at most `S` automaton states, a match, the earliest match of each position class, and aliveness for ever are all decided within `S * (W + L)` samples of the start (a repeated configuration of automaton state and position class can be cut or repeated). Never from a guessed number of unrollings. Nonvacuity is not defined on infinite traces. Laws (`tests/unit_tests/test_reference_lasso.py`, exhaustive over the lassos of two signals): a decision on the written samples is the infinite decision (outcome and sample, also for disable); the weak and strong forms of every bounded property agree; the infinite results match a 26-sample unrolling (decided attempts at the same sample, undecided ones by the finalized outcome of the unrolling).

A case with `support: oracle` marks a property the production pipeline rejects (`validation_problems` must be non-empty for it): only the reference evaluator runs it. Layers 2 and 3 assert the located rejection instead. The header is removed from a case when the pipeline supports it. The cases that keep it are the covers rejected by the cover rule and the cases of the unbounded files below that validation rejects. The weak `until`/`until_with` cases have no header, nor do an unbounded antecedent and unbounded `always` (over a bounded sequence, `not` of one, or an implication into one) for `assert`/`assume`. The strong forms the pipeline accepts for an `assert` (`strong(...)` of an unbounded sequence, `s_eventually [m:$] p` for a Boolean or bounded-sequence `p`, `s_until`, `s_until_with`, `not` of an unbounded sequence, in the positions where a weak unbounded sequence is accepted, also under `disable iff`, `$past` and `always`) have no header either: the cases of `lasso.trace`, `liveness.trace`, `unbounded.trace`, `until.trace` and the strong case of `constants.trace` that fall under it. The `cover` rejections and `s_eventually` of a property operand stay oracle-only. The accepted lasso cases also run through the liveness verdict (`tests/functional_tests/temporal_machine/CONTRACT.md`, points 52-60).

**Declared rejections.** An oracle-only case may name the rejection it expects with a `rejected-by: <fragment>` header (`tests/support/tracefile.py`). The fragment must occur, verbatim, in the joined `validation_problems` of the directive. This lets a counterexample whose property the pipeline rejects for another reason than the cover rule or a not-yet-supported construct (for example the first-sample rule for `$past`) keep its hand-derived table checked by the reference evaluator. Every other case must have no first-sample problem. At the samples where a `$past` term has no history, the reference evaluates conditions with the IEEE X rules (`docs/semantics.md` §8), so such a table is exact: `counterexamples.trace` holds CE-04 (`x ##0 (a && $past(b))[->1] |-> 1'b0` and its `[=1]` form, rejected by the first-sample rule) and fails at sample 1.

**Oracle cross-check.** For every other case, the per-attempt oracle agrees with the obligation-level one where both are defined: the first failure (`assert`/`assume` and `scope: first-failure`), the whole failure set when the property is a sequence or `not` of one, and the successes of a `cover`.

**`not` of an unbounded sequence.** The pipeline accepts `not` of an unbounded sequence in an `assert` (an `assume` when the sequence is strong), so the `scope: attempt` cases of `lasso.trace` (`not_of_a_weak_unbounded_sequence_never_b`, `not_of_a_sequence_that_matches_in_the_loop`, `not_of_a_dead_sequence`), `unbounded.trace` (`not_of_weak_unbounded_is_strong_at_the_end`), `until.trace` (`not_of_a_weak_until`, `not_of_a_strong_until`) and `liveness.trace` (`law_not_s_eventually`) have no `support: oracle` header any more, and `not_liveness.trace` (hand-derived, run by every layer) pins the verdicts: for `not S` the first match of `S` is FALSE, a dying frontier TRUE, an obligation pending for ever FALSE in the limit when `S` is weak (the negation is strong) and TRUE in the limit when `S` is strong (the negation is weak). `cover` of such a property stays `support: oracle`.

**Covers of unbounded sequences.** A cover whose property is a strong unbounded sequence (the cover default, or `strong(...)`), or an implication with a bounded single-length antecedent into one, is accepted by the pipeline, so the `scope: attempt` cover cases of `unbounded.trace` (`cover_unbounded_delay`, `cover_unbounded_pending_finalizes_false`, `cover_goto`) and `lasso.trace` (`cover_defaults_to_strong`) have no `support: oracle` header any more, and `unbounded_covers.trace` (hand-derived, run by every layer) pins the count of a cover: each attempt once, at the sample where its first match ends, attempts first-matching at the same sample giving one `pass` sample, an attempt whose frontier dies giving none, a `disable iff` true while an attempt is pending cancelling it, and an implication counting only non-vacuous successes. `cover_s_eventually`, `cover_until` and the covers the cover rule rejects stay `support: oracle`.
