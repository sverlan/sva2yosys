# Slang export → IR conversion contract

These tests cover `sva2yosys.slang.convert`: turning the document from `sva2yosys.slang.export` into canonical IR `Directive`s, or into `Rejection`s for anything outside the supported subset. Inputs are SystemVerilog fixtures and small inline sources, exported with `export_design`/`export_texts`.

## Fixtures

- `fixtures/basic_properties.sv`:
  - the eleven basic properties of the specification (`p01`…`p11`);
  - an assume, a cover and a plain sequence property;
  - sampled-value functions;
  - expressions with selects of descending, offset and ascending ranges, signed operands, conditionals, concatenation and replication.
- `fixtures/basic_defaults.sv` (in the same file): `default clocking`, `default disable iff`, a named property and sequence with arguments, and an explicit `disable iff` next to a default one.

## Contract

1. **Directive fields.**
   - `Restrict` normalizes to `ASSUME` for formal lowering (IEEE 1800-2017
     16.14.4), preserving the label/source range, clock, disable and property.
     Module, default-clock, named-property, procedural and initial contexts use
     the existing assumption rules. Unsupported clocks, disable conditions,
     sequence operators and strong assumptions remain located rejections.
   - `kind`: `Assert`→`ASSERT`, `Assume`→`ASSUME`, `CoverProperty`→`COVER`.
   - `name`, `scope` and `source` come from the record.
   - Directives and rejections keep document order.
2. **Clock.** The leading clock becomes `Clock(Signal(<clk path>, 1 bit), POSEDGE)`, whether written explicitly or taken from `default clocking`. A top-level clocking equal to the leading clock is removed from the property.
3. **Disable.**
   - A top-level `disable iff (e)` gives `disable = e`.
   - Otherwise the scope's default `disable iff` is used; otherwise `None`.
   - An explicit `disable iff` overrides the default (IEEE 1800 §16.15).
4. **Procedural assertions** (`docs/semantics.md` §6). An assertion in `always @(posedge clk)` without `sva2yosys_procedureIssue` is converted like a module-level one, with its clock (written or inferred), and:
   - its enabling condition `en` is the conjunction of the entries of `sva2yosys_enable`, an `If` entry being its expression (`!` when negated) and a `Case` entry `expr == item` for its items joined with `||` (`!` when negated);
   - a sequence property `s` (or `not`, `or`, `if` property) becomes `PropIf(en, p, None)` (which `temporal.lower` turns into `en |-> p`, fused into the antecedent when `p` lowers to an implication), an implication `a |-> c` (or `|=>`) becomes `Implication(SeqConcat(Bool(en), ##0, a), c, overlapping)`, and a `PropAnd` maps over its conjuncts;
   - without any condition, the property is unchanged.
   - **`initial` procedures** (IEEE 1800-2017 16.14.6; `sva2yosys_procedureKind` is `"initial"`). The directive has one evaluation attempt, at the first tick of its clock, so its enabling condition is `FirstSample`, applied through the same `_enabled`: `a |-> b` becomes `(FirstSample ##0 a) |-> b`, any other property `PropIf(FirstSample, p, None)`. A path condition (`if`, `else`, `case`) around it is rejected by the exporter's procedure analysis (`sva2yosys_procedureIssue`), so the converter rejects the directive with "a condition around a concurrent assertion in an initial procedure is evaluated when the procedure runs at time 0, not at the assertion's first clock tick (IEEE 1800-2017 16.14.6.2); ...", located at the assertion (the condition is evaluated at time 0, not at the first tick). A `cover` of an unbounded sequence in an `initial` procedure is a known limitation: `PropIf(FirstSample, …)` fails the unbounded-cover validation ("unbounded ranges ($) are not supported yet"), although the module-level cover is accepted (`docs/semantics.md` section 6). `FirstSample` is a one-bit unsigned value (`BIT`). The clock is the record's `sva2yosys_clock` (explicit, inferred from the block's single event control, or `default clocking`); the check that it equals the block's event applies only when the `initial` block has an event control (`sva2yosys_procedureClock` not `null`). An `initial` assertion with no clock is rejected with a located message that cites IEEE 1800-2017 16.16 (a delay or a loop in the block, `final`, `always_comb` and `always_latch` are rejected as for `always`).
5. **Properties.**
   - The converter preserves the property structure; `temporal.lower.lower` (unit-tested in `tests/unit_tests/test_lower.py`) rewrites the supported shapes before the machine, and validation rejects the rest.
   - `|->`/`|=>` become `Implication(antecedent, consequent, overlapping)`; the consequent may be any property (a nested implication, a `PropAnd`, `PropOr`, ...). No distribution over `and` happens in the converter.
   - `not p` becomes `Not(p)` for any property `p` (`not s`, `not (a |-> b)`, `not not a`).
   - `nexttime [n] p` / `s_nexttime [n] p` become `Nexttime(n, strong, p)` (`nexttime p`: `n` = 1; `[0]` kept); `always [m:n] p` / `s_always [m:n] p` become `Always(m, n, strong, p)`, and `eventually [m:n] p` / `s_eventually [m:n] p` become `Eventually(m, n, strong, p)`, for any property `p`. A procedural enabling condition wraps them as `PropIf(en, p, None)`.
   - Unbounded forms: `always p` / `always [m:$] p` become `Always(0 or m, None, False, p)`, and `s_eventually p` / `s_eventually [m:$] p` become `Eventually(0 or m, None, True, p)` (`None` is the unbounded `$`). IEEE allows `$` only there: `s_always` and `eventually` without an upper bound (Slang rejects them first; the converter rejects them again from a hand-edited export) and `nexttime` with a range are rejected with a message naming the operator. `a until b`, `a s_until b`, `a until_with b` and `a s_until_with b` become `Until(a, b, strong, inclusive)` when both operands are Boolean expressions; a sequence, repeated or property operand is rejected with "operands of 'until' must be Boolean expressions" (the name of the operator used).
   - A property `and` whose operands are both default-strength sequences is the sequence `and` (`SeqAnd`); otherwise it is a flat `PropAnd` of the operand properties.
   - A property `or` whose operands are both default-strength sequences is the sequence `or` (`SeqOr`); otherwise it is a flat `PropOr` (so `strong(a) or b` and `(a |-> b) or (c |-> d)` are `PropOr`).
   - A property `if (e) p [else q]` becomes `PropIf(e, p, q or None)`. A procedural enabling condition fuses into an implication's antecedent, maps over a `PropAnd`, and wraps any other property as `PropIf(en, p, None)` (`if (en) p`; the lowering gives `en |-> p`).
   - A bare sequence becomes `SequenceProperty` with strength `DEFAULT`; `strong(s)` and `weak(s)` (also as an implication consequent) give `STRONG` and `WEAK`.
   - Named properties and sequences are converted through their argument-substituted bodies.
6. **Sequences.** `s1 or s2`, `s1 and s2`, `s1 intersect s2`, `s1 within s2` and `e throughout s` become `SeqOr`, `SeqAnd`, `SeqIntersect`, `Within` and `Throughout`.
   - A Boolean expression becomes `Bool`.
   - Unbounded forms: `##[m:$]`, `##[*]`, `##[+]` and `[*m:$]`, `[*]`, `[+]` keep an unbounded `Delay`/`Repeat` (`maximum` `None`); `b[->n]`, `b[->m:n]`, `b[->m:$]` become `Goto(b, m, n)` and `b[=n]`, `b[=m:n]`, `b[=m:$]` become `NonConsecutive(b, m, n)` on the Boolean expression `b` (a non-Boolean operand is rejected). Validation rejects all of them for the machines (see below).
   - `[*m:n]` and `[*n]` become `Repeat`, also on a parenthesised sequence such as `(b ##1 c)[*2]` (Slang's `SequenceWithMatch` without match items).
   - In a concatenation, a first element with delay `[0:0]` is the sequence itself; any other leading delay becomes `SeqConcat(TRUE, Delay, s)`. Later elements chain to the left: `((s1 ##d2 s2) ##d3 s3)`.
7. **Expressions.**
   - Each node keeps Slang's result type as `ValueType(width, signed)`; `logic`, `bit`, `int`, `integer`, `byte`, `shortint` and `longint` are recognised.
   - A node Slang folded or can evaluate as a constant (a literal, `-8'sd3`, a parameter expression, `$bits`, …) becomes one `Const` of the node's type, its value being the two's-complement bit pattern; a constant with X/Z bits is rejected.
   - Bit and part selects map to bit positions of the value: `v[2]` on `[3:0]` is bit 2; `off[5]` on `[7:4]` is bit 1; `asc[0]` on `[0:3]` is bit 3.
   - Signals keep their hierarchical path.
   - Sampled-value functions become `Sampled`.
   - `$countones(v)` becomes the sum of `v`'s bits, each converted to `int`, as a balanced tree (a 4096-bit operand compiles); `$onehot(v)` becomes that sum `== 1`, and `$onehot0(v)` that sum `<= 1`.
8. **The eleven specification properties** convert to the exact IR given in the tests.
9. **Rejections.** Each of the following rejects the assertion, with a message naming the construct and a source position. Other assertions are unaffected.
   - Context:
     - an assertion without any clock (the message cites IEEE 1800-2017 16.16);
     - a procedural concurrent assertion with `sva2yosys_procedureIssue` (its message), whose clock differs from its block's event, or whose enabling condition uses a sampled-value function;
     - `cover sequence` and `expect`.
   - Clocking and reset:
     - a `disable iff` with `sva2yosys_disableIssue` (its message): it reads a signal that may change at the clock edge, e.g. a register;
     - `negedge` clock, `edge` (both edges) clock, a clock that is not a 1-bit signal;
     - `iff` clock;
     - multiclock property (`multiclock SVA properties are not supported yet`).
   - Sequences:
     - sequence match items (local variable assignments);
     - `first_match`; an operand of `and`/`intersect`/`within` that can match empty (validation).
   - Properties:
     - property operators other than implication, `and`, `or`, `not`, `if`, `nexttime`/`s_nexttime`, `always`/`s_always`, `eventually`/`s_eventually` and the `until` family (e.g. `implies`, `#-#`);
     - the operands of the `until` family that are not Boolean expressions;
     - `s_always` and `eventually` without an upper bound, and `nexttime` with a range or a `$` bound, with a message naming the operator;
     - a property `if`/`else` whose condition uses `$past` (X at the first samples selects `else`, while the first-sample rule would force both guards false).
     - Nested implications, `or` of non-sequences, `not` of non-sequences and `if`/`else` with other branches are converted; validation (`passes/validate.py`, after `lower`) rejects them, so the rewrite and the CLI still report them as located rejections.
     - The unbounded constructs are converted for the reference semantics. Validation accepts an unbounded antecedent into a bounded consequent and unbounded `always` over a sequence, `not` of one or an implication into one (`assert`/`assume`; a `cover` of them is rejected); everything else is rejected by validation with a located message each: "unbounded ranges ($) are not supported yet" (also for unbounded goto and nonconsecutive), "goto repetition [->] is not supported yet", "nonconsecutive repetition [=] is not supported yet", "unbounded 'always' (no upper bound) is not supported yet", "unbounded 's_eventually' (no upper bound) is not supported yet" and "'until' is not supported yet" (likewise `s_until`, `until_with`, `s_until_with`), anywhere in the property.
   - Expressions:
     - hierarchical reference;
     - variable bit select, out-of-range constant bit index, indexed part select (`+:`/`-:`);
     - system functions other than the five sampled-value functions, `$countones`/`$onehot`/`$onehot0` and `$isunknown`;
     - `$countones`/`$onehot`/`$onehot0` of an operand using `$past` (X bits count as 0, so the first-sample rule would be wrong);
     - `$past` with a gating or clocking argument (`$past(e, n, gate)`); a depth below 1 is already a Slang error;
     - nested sampled-value functions;
     - user function call;
     - `**`;
     - wildcard equality;
     - constants containing x/z;
     - non-integral types;
     - any node marked `sva2yosys_unsupported`.
     - a name that means something else where the assertion is written: e.g. a `default disable iff (rst)` of the module used by an assertion inside a generate block that declares its own `rst` (`sva2yosys_visibleAtSite` is false). Generated monitors connect signals by name at the assertion's position.
   - A `disable iff` below the top of a property never reaches the converter, because Slang reports `NestedDisableIff` at compile time; the converter still rejects it defensively.
10. **Format errors.** A document with another `format` or `formatVersion` raises `FormatError`. So does a record without `sva2yosys_disableIssue` (or a procedural one without its procedure analysis), or with a value that is not a string or null: a missing timing analysis must not pass silently.

11. **`$isunknown`** (`docs/semantics.md` §8a). The model is two-state, so `$isunknown(e)` is the constant 0. `convert(document, x_checks)` takes `XChecks.SKIP` (the default) or `XChecks.REJECT`.
    - **Folding.** With `SKIP`, a call whose operand is not constant becomes `Const(0, <type of the call>)`; its operand is still converted, so an unsupported construct inside it is rejected as anywhere else, and it is checked as validation checks every expression before it is discarded: an operand that could be X from known values is rejected, located at the call (a divisor of `/` or `%` that is not a non-zero constant: `$isunknown(a / b)` is 1 when `b` is 0, §1), while `$isunknown(a / 2)` is folded. A call Slang already evaluated (a constant operand, e.g. `$isunknown(4'b0001)`) is an ordinary constant of the node and is not an X-check: `$isunknown(4'b1x00)` is the constant 1 (IEEE 1800 §20.9), so `assert property (!$isunknown(4'b1x00))` converts and always fails.
    - **Expressions are folded** (`passes/x_checks.py`) in a directive that uses `$isunknown`: `!$isunknown(s)` is 1, `b && !$isunknown(c)` is `b`, `a || $isunknown(c)` is `a`, `$isunknown(c) ? x : y` is `y`. The folded value is that of the unfolded expression on every input.
    - **Skipped.** A directive for which the structural criterion of `passes/x_checks.py` proves that nothing remains to observe is not converted: `Conversion.skipped` holds a `Skipped` (scope, name, kind, reason starting with `X-check:`, the directive's source) instead of a directive, in document order. The criterion is applied to a directive that used `$isunknown` only, on the folded property: an `assert`/`assume` that cannot fail (`!$isunknown(s)`, `v |-> !$isunknown(s)`, `$isunknown(s) |-> p`, `not $isunknown(s)`, a property `and` of such parts), a `cover` that cannot succeed (`$isunknown(s)`, `$isunknown(s) |-> p`, `v ##1 $isunknown(s)`), a `disable iff` that folds to true (always disabled), and a procedural enabling condition that folds to false (no attempt ever). A `disable iff` that folds to false is removed (never disables) and an enabling condition that folds to true is dropped, each with a warning.
    - **Never skipped when it could fail.** `a |-> $isunknown(s)` (fails whenever `a` holds), a cover `v |-> !$isunknown(s)` (succeeds when `v` does), `a |-> !$isunknown(s) && b` and every property the criterion cannot decide are converted, with the folded constants in place, and carry a `ConversionWarning` (scope, name, a message saying the X part is dropped and what remains, the location of the first `$isunknown` call, the directive's source). A strong form is never proved.
    - **Rejected.** With `REJECT`, every directive that uses `$isunknown` is rejected, located at the call, naming `$isunknown` and the option. With either option, a call whose operand uses `$past` is rejected, located at the call: `$past` is X at the first samples (`docs/semantics.md` §8), where the 4-state `$isunknown` is 1, so it must not silently become 0 there. `$isunknown` of an operand without `$past` (also of `$rose`, `$fell`, `$stable`, `$changed`, always known) is folded; `$isunknown` inside a sampled-value operand (`$past($isunknown(s))`, `$past(!$isunknown(c))`) is rejected (point 13).
    - Other assertions are unaffected, and the order of directives, rejections, skipped and warnings follows the document.

13. **Default sampled values** (`docs/semantics.md` section 8). `Signal.default` is `SampledDefault.X` or `KNOWN`, read from the exporter field `sva2yosys_sampledDefault` (frontend contract, point 24); a `NamedValue` without it, or with another value, is a located rejection (an internal export error), never read as X. Validation rejects a directive that has a `$past`, `$rose`, `$fell`, `$stable` or `$changed` call, at any depth and in the `disable iff` condition too, whose operand is not all X before the first clock tick (IEEE 1800-2017 section 16.5.1): an operand with a known default signal (2-state type, initializer) or a constant bit that is not absorbed (`{1'b1, a}`, `a & 4'b0011`). The message names the cause and says that a `disable iff` does not help. Three constructs inside a sampled operand are rejected by the converter because the IR would hide a known default: a cast to a 2-state type (the exporter field `sva2yosys_fourState` of every `Conversion` is false; a missing field is an internal export error), `$countones`/`$onehot`/`$onehot0` (X bits count as 0, §20.9), and `$isunknown` (1 for an X operand); each with a located "before the first clock tick is not unknown ... does not support it inside a sampled-value function" message, e.g. `$fell(bit'(a))`, `$stable($countones(v))`, `$past(a | $isunknown(a))`. A cast to a 4-state type is accepted. `a + 1`, `a[3:0]`, nets and uninitialised 4-state variables and input ports are accepted.

14. **Packed integral operand types** (`test_slang_convert_integral_types.py`). The width and signedness of every expression come from the exporter field `sva2yosys_integral` (frontend contract, point 26), never from the type string. Accepted as whole values: enums (an enum member is a constant of the enum's width; `enum {A, B}` is a 32-bit signed value, `enum logic [1:0]` two unsigned bits), typedefs, `int unsigned`, packed structs and multi-dimensional packed arrays (compared as flat vectors). Rejected with a located message: a bit or part select of a value with more than one packed dimension or of a packed struct/union ("selects into multi-dimensional packed arrays or packed structs are not supported yet"), member access (`unsupported construct`), unpacked arrays and `real` ("unsupported type '<type>' (only packed integral types)"). A node without the key is an internal export error naming `sva2yosys_integral`; the value `false` is "unsupported type" as above. An enum with a 2-state base type is 2-state: `$past(e)` on it is rejected by the default-sampled-value rule (point 13), while a 4-state (`logic`-based) uninitialised enum is accepted.
15. **Conversions** (`test_slang_convert_implicit_conversions.py`, IEEE 1800-2017 11.8.2, 11.8.3, 6.24.1). An operand converted to the type of its context (Slang kind `Propagated`) is extended by the sign of the context's type, so a signed operand in an unsigned sum, relation or `?:` is zero-extended; casts and the conversion of an actual argument to a typed formal (kind `Explicit`) extend by the signedness of the source (`8'(s4)` with `s4 = -1` is `8'hFF`, `signed'(u4)` reinterprets). A `Conversion` without `sva2yosys_conversionKind` is a located internal export error. Slang's `Implicit` kind did not occur in assertion expressions. Hand-derived values are evaluated through the reference evaluator.
16. **Set membership `inside`** (`test_slang_convert_inside.py`, oracle `tests/support/inside_reference.py`, IEEE 1800-2017 11.4.13). `e inside { items }` is lowered to the IR as an OR over the items, with no new node: a value item is `e == item`; a range item `[lo:hi]` is `lo <= e && e <= hi` (a range with `lo > hi` therefore matches nothing, and `{}` is the constant 0); a constant item with X, Z or `?` bits is a wildcard (the right operand of `==?`, 11.4.6) and becomes `(e & m) == (item & m)` with `m` clearing the wildcard bits (the only place where a constant with x/z bits is accepted; inside a sampled-value function it is rejected, since a wildcard bit would match the X of the first sample, 16.5.1). **Only uniform lists are accepted**: the left operand, every value item and every range bound must have one width and one signedness, each operand sized by itself (its natural type: below Slang's conversions to the context type; an arithmetic or conditional operand combines its operands' natural types; a shift has its left operand's; an unbased unsized literal is one unsigned bit). 11.4.13 does not say whether each comparison is sized on its own or all share one context, and tools read it differently; for a uniform list every reading gives the same comparisons, so the lowering is the same under all of them. Any other list is rejected, located at the first operand whose type differs, with a message naming both types and saying that tools size such lists differently (`v4 inside {1}`: `1` is a 32-bit signed integer, use `4'd1`; `v4 inside {'1, 8'h00}`; a signed left operand with an unsigned item). The lowering equals the oracle on every value of the 3- and 4-bit operands of the tested uniform lists (unsigned and signed operands, wildcard items, ranges with negative bounds, signal items and bounds, an arithmetic left operand). A `$` bound is the lowest or highest value of the left operand's type (11.4.13): its comparison always holds and is dropped (`[$:hi]` is `e <= hi`); the left operand must be a leaf with the comparison's signedness, (`[$:$]` is a Slang error). An `inside` inside a sampled-value function, one with a sampled-value function in an item or bound, and a wildcard item with a sampled-value function in the left operand are rejected: an X item is all wildcards (11.4.6, 11.4.13), so `v inside {$past(w)}` holds at the first sample, which the two-state lowering does not give (found in a review). An unbased unsized literal (`'0`, `'1`) fills its own comparison (5.7.1): a list where Slang's common width is wider than the comparison's is rejected (`v4 inside {'1, 8'h00}`); `'x` and `'z` items are rejected. The checks also run on an `inside` that Slang folded into a constant, nested in a larger folded expression, or used in a constant integer the converter consumes (bit and part select indices, replication counts, `$past` depths): `v4[(4'd15 inside {'1, 8'h00})]` is rejected (per comparison `'1` fills 4 bits and matches 15, in Slang's 8-bit context it does not). An `inside` that the exporter does not trust by position (frontend point 27: neither an assertion operand reached through run-time operators nor run-time design code; e.g. a parameter or its override, a declaration, a generate condition, a function, a port connection, a select or replication inside an assertion; `sva2yosys_constantInsides`) gets the same uniformity check, and a non-uniform one rejects every directive of the design (located at that `inside`); a uniform one is accepted (e.g. `if (AGENT inside {S, M})` over one enum type). One that the exporter cannot find among the typed expressions (a bound, an argument or default argument of a sequence or property, the width of a size cast, a type dimension: `sva2yosys_insideIssue`) rejects every directive, with a message saying that Slang evaluates it as a constant. One in run-time design code (continuous assignments, procedural blocks outside their declarations, an immediate assertion in an `initial` block) is not checked: Yosys reads it, and it folds into no assertion. Each `inside` is checked once, so nesting is linear. Rejected with a located message: an unpacked-array or other non-integral item, an X/Z bit in a range bound.

17. **Parameters that cannot key a monitor** (`test_slang_convert_parameters.py`). The monitor of each elaborated instance is selected by comparing the integral values of the parameters visible at the assertion (`docs/architecture.md`, *Source rewriting*), and output generation refuses a site where one of them cannot be compared. The conversion applies the same rule, through the one shared predicate `sva2yosys.ir.directive.uncomparable_parameters`, so check mode and generation refuse the same directives: a directive with a visible parameter whose value is not an integer (a `$` such as `parameter upper = $`, a string, real or type parameter, an interface port) or whose name is not a plain identifier is a located **rejection** (`Rejection`, source of the assertion), with the text of `uncomparable_message`, naming every such parameter (sorted, comma-separated). The same holds for a directive that would otherwise be skipped by an X-check. **Only the parameters the monitor depends on count:** the check looks at the names of `sva2yosys_dependencies` (`Directive.dependencies`, `Skipped.dependencies`; `null` counts every visible parameter), so a non-comparable parameter that the assertion cannot depend on (`parameter axi_cfg_t cfg` used only in an enclosing `if (cfg.X)` generate condition, a type parameter that no signal read by the assertion uses) is not a rejection. A directive whose visible parameters are all integers, or that sees none, is unchanged; a rejection for another reason keeps its own message. A literal `$` in a range (`##[0:$]`) is not a parameter and stays supported. A parameter or type parameter the assertion depends on that its position hides behind another declaration of the same name (`sva2yosys_hiddenParameters`: an inner block redeclares `D` that a named property uses) is rejected with a located error naming it, on every path: the visible parameters cannot key the monitor on a name they do not contain, so an instance that overrides the hidden one would select the wrong monitor.
