# Generated monitor contract (Layer 3, opt-in)

These tests run generated monitors (`sva2yosys.codegen.systemverilog.monitor_module`) through the free Yosys/SBY flow. They need SBY (`SVA2YOSYS_SBY`) and are skipped unless the run selects it (`--external-tools=sby` or `all`). Points 1 and 4 (every trace table, every expression) are marked `slow` and run only with `pytest --slow`.

## How a case runs

For every trace case of `tests/functional_tests/reference_semantics/fixtures/*.trace`:

1. The case's directive is converted and compiled as in Layers 1 and 2, then its monitor module is generated.
2. A generated testbench drives the trace:
   - a sample counter, starting at 0, incremented on every `posedge clk`;
   - signals taken from a `case` on the counter (0 beyond the trace);
   - the monitor instantiated with `CHECK = 0`.
3. The testbench asserts, at every sample `t` of the trace, that the monitor's `fail` equals the table's `fail` row (for `assert`/`assume` cases) and that `success` equals the `pass` row.
4. `sby` (bmc, `multiclock off`, `read_verilog -formal -sv`) is run with depth equal to the trace length, inside `tmp_path`.

## Contract

1. **Every trace table passes through hardware.** For each case, the BMC run passes: in every sample, the generated monitor's `fail`/`success` outputs equal the table. This confirms the timing table (`docs/semantics.md` §4) and the first-sample, disable and cover rules in the generated SystemVerilog.
2. **The checks fire, per directive kind.** With `CHECK = 1`:
   - `assert`: SBY (bmc) reports exactly one failed assertion, at the first expected failure sample; a failure masked by `disable iff` is not reported.
   - `cover`: SBY (cover) reaches the cover statement at the first expected success sample; a match masked by `disable iff` is not reported.
   - `assume`: `assume property (a |-> ##2 b)`, with `a` true only at sample 1 and `b` a free input, forces `b` at sample 3 (a testbench assertion on `b` there passes, and fails with `CHECK = 0`) but not at sample 2 (the same assertion there fails).
3. **Deterministic output.** Generating twice gives identical text.
4. **Expression values match the reference.** For every condition in `fixtures/expressions.txt` (every IR expression node and operator; unsigned, signed, mixed-signedness and mixed-width operands; sampled-value functions of vectors), the condition is asserted on 24 seeded random samples (half of the values are corner values) of `a`, `b` (1 bit), `u`, `v` (4 bits) and `w` (8 bits), unsigned, and `s` (4 bits) and `z` (8 bits), signed. The expected `fail`/`pass` rows come from the reference evaluator, and the run passes as in point 1. Each condition must both fail and hold on its samples.
5. **Only reachable letters are registered.** For representative properties (`##[1:3]`, `##4`, `##[1:32]`, a repetition), `machine_size(...).temporal_bits` is the hand-derived count of age-reachable letters, and after `prep` the monitor's flip-flops hold at most that many bits (needs `SVA2YOSYS_YOSYS`). `a |-> ##[1:32] b` thus registers 63 bits instead of the 1056 of the unpruned machine.
6. **Optimised forms reproduce the tables** (marked `slow`). Every trace case also runs, as in point 1, through each optimised form that applies to it (`optimize.forms`). The `history` form must match the whole table. The `window` form, exact only up to the first failure, must match the `fail` rows up to and including the first expected failure.
7. **Strength does not change a monitor.** For a bounded sequence, `strong(s)`, `weak(s)` and `s` give the same monitor text in `assert`, `assume` and `cover`: strength only decides attempts pending at the end of a finite simulation, which formal verification never reaches (`docs/semantics.md` §9.1).
9. **Oracle-only cases are rejected.** A trace case marked `support: oracle` (a property the pipeline does not support: a cover the cover rule of `docs/semantics.md` §9.5 rejects, and the unbounded constructs of `unbounded.trace`, `liveness.trace`, `until.trace` and `lasso.trace` that the pipeline does not support yet) generates no monitor: `validate_directive` raises a `CompileError` for it, without running SBY. A case with a `rejected-by: <fragment>` header (for example a counterexample rejected by the first-sample rule) is rejected by `validate_directive` and `compile_monitors` with a message containing that fragment, verbatim.
10. **Per-attempt monitors** (the full set marked `slow`). Every `scope: attempt` case that is not oracle-only compiles (`temporal.compile.compile_monitors`) to exactly one monitor and runs through its monitor module as in point 1. For a per-attempt machine, `fail` and `success` equal the table at every sample (`fail` not compared for `cover`). For a canonical machine (a `temporal.trace` case such as `assert property (always [1:2] b)`), `fail` equals the table up to and including the first expected failure, and for a `cover` `success` equals the table at every sample. Weak and strong forms of `nexttime`, `always` and `eventually` give the same monitor text (as point 7 for sequences). One representative case runs in the default suite, and so does a monitor with no temporal registers (`not (a |-> b)`).
11. **Unbounded antecedents and unbounded `always`**. The cases of `unbounded_antecedents.trace` and the accepted cases of `unbounded.trace`, `liveness.trace` and `lasso.trace` run as in points 1 and 10 (the full set under `slow`): the canonical monitor's `fail`/`success` equal the table of a `scope: attempt` case up to and including its first expected failure, and of the other cases at every sample. The representative matrix runs with `--extended`, with a small subset by default (`##[1:$]` with `assert` and `assume`, a `[*1:$]` antecedent with `|=>`, goto, nonconsecutive repetition, `always [2:$]` over an implication, an implication into `always`, `disable iff` with `$past`). With `CHECK = 1`, `assert property (always b)` fails at the first sample where `b` is low. The optimised forms do not apply to them (no table runs through `window` or `history`; asking the generator for one is a `ValueError` saying so), the output is deterministic, and strength does not change the monitor of an unbounded-antecedent implication (a `cover` of one is rejected).
12. **Weak unbounded consequents**. The cases of `unbounded_consequents.trace` and the now-accepted `scope: attempt` cases of `unbounded.trace`, `liveness.trace` and `lasso.trace` (weak, `assert`/`assume`) run as in points 1 and 10 (the full set under `slow`) through the configuration-set monitor (`form: configurations`): `fail` equals the table up to and including its first expected failure and covers every later table failure sample's attempt as for point 11; the representative matrix is split between default and `extended` (`a |-> ##[1:$] b`, `a |-> b[*1:$] ##1 c`, `a |=> b[->2]`, `disable iff` with `$past`, `always (a |-> b[*1:$] ##1 c)`). With `CHECK = 1`, `assert property (a |-> b[*1:$] ##1 c)` fails under SBY at the reference's sample and `assert property (a |-> ##[1:$] b)` is proved. Overlapping attempts in different configurations fail at the reference's sample. The optimised forms do not apply (a `ValueError` saying so). Output is deterministic.
8. **Property `and`.** For the `scope: first-failure` cases, one monitor per conjunct is generated and the testbench ORs their `fail`; `fail` must equal the table up to and including the first failure only, and `success` is not checked (undefined). The optimised forms are not run on these cases (each conjunct picks its own).
13. **Constants**. The cases of `constants.trace` run as in points 1, 10 and 12 (the full set under `slow`, small representatives of each machine kind by default, with the remaining matrix under `extended`): the canonical monitor (`a |-> ##1 1'b0`, with `disable iff` at the decisive sample), the configuration-set monitor (`a |-> ##[1:$] 1'b0`, `a |-> b[*1:$] ##1 1'b0`) and the per-attempt monitor (`(a |-> ##1 1'b0) or (c |-> d)`) report `fail`/`success` as the table at every sample (up to and including the first failure for a `scope: attempt` case of the canonical or configuration machine). A constant-false letter is a guard on the condition `1'b0` and is held at no sample, so the monitor needs no case for it.
14. **Weak `until` / `until_with`**. The weak cases of `until.trace`, `liveness.trace` and `lasso.trace` and the cases of `until_machine.trace` run as in points 1, 10 and 12 (the full set under `slow`, a representative matrix split between default and `extended`: `a |-> b until c`, `a |-> b until_with c`, `always (a |-> b until c)`, a `$past` operand) through the configuration-set monitor (`form: configurations`).
15. **Covers of unbounded sequences**. The cases of `unbounded_covers.trace` and the now-accepted cover cases of `unbounded.trace` and `lasso.trace` run as in points 1, 10 and 12 (the full set under `slow`) through the configuration-set monitor: `success` equals the table's `pass` row at every sample. The representative matrix runs with `--extended`, with a small subset by default (`cover property (a ##[1:$] b)`, `a[*2:$] ##1 b`, `b[->2]`, `a |-> ##[1:$] b`, `a |=> b[*1:$] ##1 c`, `disable iff` during a pending attempt, a constant-false condition). Under SBY in cover mode (`CHECK = 1`, a free-running trace driven by the table) the cover statement is reached exactly at the first sample of the table's `pass` row (SBY leaves step 0 out of its summary; `support.toolchain` reads a reached cover or failed assertion without a step as step 0), and is unreachable (the cover task reports it unreached) for a table with an empty `pass` row (`cover property (a ##[1:$] 1'b0)`, and an attempt whose frontier dies). The cases of `scope: attempt` covers rejected for the reasons of `temporal_machine` point 46 generate no monitor.
16. **`$isunknown`**. The cases of `isunknown.trace` (a directive with an `$isunknown` part and checks left, hand-derived as the directive without the X part) run as in points 1 and 2 (the full set under `slow`, a fast representative by default): `fail`/`success` of the generated monitor equal the table at every sample, so a mixed directive is exactly the directive without its X part.
17. **Strong liveness** (`docs/semantics.md` §9.6). The monitor of an `assert` with a strong unbounded consequent (`ConfigMachine.liveness` set) has a liveness part, entirely inside `` `ifdef SVA2YOSYS_LIVE `` ... `` `endif ``:
    - **Without the define the monitor is the weak one.** Removing the define block from the text gives, apart from the `// source:` line, exactly the monitor of the same property with the weak strength (`strong(a ##[1:$] b)` against `weak(a ##[1:$] b)`, `s_eventually b` against `weak(1'b1[*0:$] ##1 b)`, the sequence it lowers to, made weak): the `prove` task sees the safety monitor only. A weak or bounded directive has no define block at all.
    - **PENDING** (one configuration): the block names `busy` (the configuration register) and asserts `s_eventually !busy` in `always @(posedge clk)` under `CHECK`. **WITNESS** (several): the block adds `pick = $anyseq`, one witness register per consequent letter (`wit_q`, step as `temporal.liveness.witness_step`) and `busy = |wit_q`, and the same check.
    - **Two SBY tasks per lasso.** For every accepted trace case with a `loop:` row (and `scope: attempt` or not) whose machine has a liveness part (the promoted cases of `lasso.trace`, `constants.trace`, `liveness.trace`, `until.trace`, `unbounded.trace`, and `strong_liveness.trace`), a test bench drives the samples from a ROM that loops (a counter `t` running `0 .. N-1` then back to `loop`), instantiates the monitor with `CHECK = 1`, and two tasks run: `prove` (`abc pdr`, no define) and `live` (`mode live`, `engines aiger suprove`, `-D SVA2YOSYS_LIVE`, through `SVA2YOSYS_SBY_LIVE`). The expectation comes from the reference (`lasso_attempt_results` on the unrolled lasso, as `temporal_machine` point 57): `prove` fails exactly when some attempt is FALSE at a finite sample. When `prove` passes, `live` fails exactly when some attempt is FALSE (then only in the limit).
    - **The combined-task mutant.** When `prove` fails, `live` is also run and passes (live mode turns the safety assertions into assumptions, so the failure is hidden): a strong directive holds only when both tasks pass. The review case `a[*1:2] |-> strong(c ##[1:$] b)` with `(a, c, b)` = `(1,1,0), (1,0,0)`, then `(0,0,0)` for ever (the safety part fails at sample 1 and the obligation launched at sample 0 stays pending) is among them.
    - **One switch per monitor.** SBY's `live` mode decides a task by the first justice verdict only (SBY issue 378), so two liveness parts in one task can hide a failure. The define block is guarded by the monitor's own define, `SVA2YOSYS_LIVE_<part>` (`<part>` is the module name without the `__sva2yosys_` prefix, e.g. `p0`, `p2_c1`; `emit_configurations.live_define`), which `SVA2YOSYS_LIVE` defines for every monitor: two `ifdef`/`endif` pairs, the first only defining the monitor's name. An `assert` is switched on by those two defines and by no other (`SVA2YOSYS_LIVE_FAIR` does not reach it). Without the define block the text is unchanged (the weak-monitor rule above). With one part switched on, the failing part of a design fails and the holding one passes, in either source order (`rewrite` contract, point 25).
    - **The witness does not re-pick.** `a |-> strong(##[1:$] b)` with `a = b = 1` at every sample passes both tasks (every obligation ends one sample after its launch; a witness that re-picks in the sample it is freed would fail `live`).
    - A fast representative runs by default (PENDING: `a |-> s_eventually b`, true and false in the limit; WITNESS: `a |-> strong(##[1:$] b)`, the `a = b = 1` case and one false in the limit), the full set under `slow`. The finite-row comparisons of the same cases through the monitor (points 1, 10, 12 and 14) still hold.
18. **`not` of an unbounded sequence** (`docs/semantics.md` §9.6). The monitor of a negated machine (`ConfigMachine.negated`) has `fail` where the sequence matches and `success` where its frontier dies; a non-negated monitor is unchanged (byte-identical, the digest test of point 13).
    - **Liveness block by strength.** `not weak(S)` (default, `weak(...)`, `until`, `until_with`) has the liveness block of point 17 (PENDING with one configuration, WITNESS otherwise). `not strong(S)` (`strong(...)`, `s_until`, `s_until_with`, `s_eventually`) has no `` `ifdef SVA2YOSYS_LIVE `` at all. Removing the define block of `not weak(S)` gives, apart from the `// source:` line, exactly the monitor of `not strong(S)` of the same sequence (`not (a until b)` against `not (a s_until b)`, `not weak(a ##[1:$] b)` against `not strong(a ##[1:$] b)`).
    - **Two SBY tasks per lasso, `not weak(S)`.** As point 17, the expectation from the reference: `prove` fails exactly when some attempt is FALSE at a finite sample (an obligation matches), and when it passes `live` fails exactly when some attempt is FALSE only in the limit (an obligation pending for ever). The representative matrix (small default controls, remaining cases under `extended`): `not (a until b)` (L1) and `not (a ##[1:$] b)` (L2) with `a = 1`, `b = 0` for ever (prove passes, live fails), `a = b = 1` (prove fails), `a = b = 0` (both pass), and a two-sample loop. Every accepted `assert` lasso case of `not_liveness.trace` and the promoted cases (point 17's set) under `slow`.
    - **`not strong(S)` through `prove` only.** The representative matrix (default and `extended`): `not strong(a ##[1:$] b)` and `not (a s_until b)` with `a = 1`, `b = 0` for ever pass (a pending obligation is TRUE), `not strong(a ##[1:$] b)` with `b` high fails, `not s_eventually b` fails at the first `b`. Under `slow`, every lasso case of `not_liveness.trace` with such a machine: `prove` fails exactly at a finite FALSE and no attempt is FALSE only in the limit.
19. **Strong `assume` as a fairness constraint** (`docs/semantics.md` §9.6; `test_fairness_monitors.py`, `test_liveness_monitors.py`). The monitor of an `assume` with a liveness part (PENDING: one configuration) has the define block of point 17 with `always @(posedge clk) assume property (s_eventually !busy);` in place of the `assert`, `busy` the configuration register. A WITNESS `assume` generates no monitor (the compiler rejects it, `temporal_machine` point 70).
    - **The fairness define.** A fairness constraint holds in every run, so the block of an `assume` is also switched on by `SVA2YOSYS_LIVE_FAIR` (a third `ifdef` before the block, defining the monitor's name). Each per-part task defines it when the design has a fairness `assume`; without it the part's task loses the constraint (`rewrite` contract, point 25).
    - **Without the define the monitor is the weak one**: removing the block from the `assume` monitor of `a |-> s_eventually b`, `a s_until b`, `not (a until b)` gives, apart from the `// source:` line, the monitor of the weak or `not strong` property of point 17/18; the block has no `assert property`.
    - **Two SBY tasks on a design with free inputs and an assertion** (a design with only assumptions is an SBY error, `yosys_contract` point 12). The expected statuses are hand-derived. `assume req |-> s_eventually ack` with `assert req |-> s_eventually ack`: `live` passes, `prove` passes, and `live` fails without the assume monitor. The same assume with `assert req |-> s_eventually (req && ack)`: `live` fails (a fair trace with `req` once and `ack` only later exists). `assume not (a until b)` (fair: `a && !b` does not hold for ever) with `assert s_eventually (!a || b)`: `live` passes, and fails without the assume.
    - **Mutants are caught**: a monitor whose block is the invariant `assume (!busy)` at every sample (built by editing the generated text) passes the second case (it forces `ack` with every `req`); a monitor without the liveness block fails the first.
    - **The `prove` task does not see the fairness constraint**: with `assume !ack`, `assume req |-> s_eventually ack` and the safety assertion `!req`, `prove` fails (a conservative result: no fair trace has `req`), identically to the design whose assume monitor has the block removed.
    - **Boundary cases** (inputs driven inside the design, `ack = 0` for ever, `assert s_eventually ack`, so `live` fails exactly when the assumption admits the trace): `assume disable iff (d) req |-> s_eventually ack` with `req = 1` and `d` toggling at every sample is admitted (`live` fails), with `d` high at the first sample only it is ruled out (`live` passes); `assume $past(req) |-> s_eventually ack` with `req = 0` for ever is admitted (`live` fails). (A pulse of `disable iff` between clock edges is not tested: monitors require `multiclock off`, where it cannot occur; the asynchronous clear is pinned by `yosys_contract` point 6.)
20. **Bounded local expressions** (`test_expression_depth.py`). Every accepted monitor must load and process in Yosys without generated-expression-depth failures. The shared expression helpers bound joins and concatenations to eight operands per group; local syntax depth is at most 32, independently of temporal range size. Named intermediates are combinational, exactly sized and preserve Boolean identities, bit order, expression types and event timing. The bound applies to DIRECT, WINDOW, HISTORY, configuration, per-attempt and liveness code, including code compiled without a liveness engine.
    - Regression matrices cover antecedent repetitions at N=1000/4096 and dense-safe consequent delays, repetitions and delay windows at N=16/32/64, all directive kinds where legal, with Yosys load/hierarchy/proc and actual SBY preparation. The SBY matrix uses ABC PDR, `CHECK=0` and a free-input assertion with an intentional counterexample: the expected status is FAIL, never ERROR. Both monitor outputs remain in its cone; this is a preparation/engine-handoff check, not a semantic oracle. The configured SMTBMC helper exceeds its own Python recursion limit at N=4096 after preparation; no engine-wide scalability guarantee is made.
    - Fast representatives remain in the default run; the larger matrix is slow. With `sby_live_tool`, a strong `a |-> strong(##[1:$] b ##7 c)` monitor runs with `SVA2YOSYS_LIVE` defined, exercising wide witness intermediates. Its live task fails: a trigger followed by `b=0` forever leaves an obligation pending. Structural depth checks include the live block without requiring that tool.
    - A wide mixed-width concatenation with a signed operand must preserve unsigned concatenation semantics through generated-code assertions; empty/singleton joins and chunk boundaries are covered by the helper unit contract. The hand-derived SBY miter for `a[*1:1000] |-> b` proves `fail = !rst && a && !b` and `success = !rst && a && b` at every sample. Existing reference/trace tests remain the independent semantic checks.
    - **Declaration order (review counterexample).** Chunked slot, history, configuration, per-attempt, concatenation and live-enabled witness monitors must elaborate in Slang too: every simple name is declared before use. Intermediates are declared before condition/temporal code and assigned after operand declarations, in their own macro scope. The depth audit includes clocked register assignments, and route cases assert their typed machine class, with an explicit wide per-attempt gate. A frozen earlier configuration monitor is compared against the current one by a checked-in SBY equivalence miter at every sample.
    - A zero-count replication within a concatenation, e.g. `{s, {0{a}}}`, is rejected by the frontend with a located unsupported `void` type; it never reaches the positive-width emitter interface (boundary checked after a review).
21. **Compact DIRECT pipelines**. Recognized guard-bearing chains and contiguous Boolean delay windows use packed shift-register pipelines with logic only for structurally reachable letters at each age. Selection depends on the compiled automaton, not source syntax. Other DIRECT shapes retain the dense fallback; forced HISTORY and WINDOW behavior and strategy selection are unchanged. Registered temporal bits equal the canonical reachable-bit counts.
    - A frozen post-6a dense emitter lives in test support and is never imported by product code. With checks disabled, SBY/ABC PDR compares its success and failure with compact DIRECT at every sample, including after failures. Cases cover legal N=0/1/2/3/8 boundaries, exact delays, fixed Boolean repetitions, contiguous delay windows, overlapping triggers, `|->`/`|=>`, reset, sampled-value warm-up, constants, negation, and assert/assume/cover. Illegal nullable boundaries remain negative cases; empty automata retain their exact events. A deliberate pipeline timing or discharge mutant must fail the equivalence check. Hand-derived traces and the independent reference evaluator remain additional oracles.
    - Independent checked-in sample-rule miters derive the events for exact delay two, repetition three and window one through three by hand. A discharge mutant keeps an accepted obligation alive: a trigger only at sample zero and a match only at sample one must produce no later failure, while the mutant can fail at sample three. The equivalence test must catch it without masking events after any previous failure.
    - Actual frozen-dense N=16/32/64 delay, repetition and window controls load/process in Yosys and complete SBY preparation. Configuration/per-attempt stress uses default budgets: `a |-> ##[1:$] b ##7 c` (129 configurations; `##8` rejects) and `always [0:80] (a |-> nexttime [80] b)` (6719 registers; 81 rejects at the 20000-instance budget). Cached predecessors restore the latter's default admission without the larger 6c work override. Rejections are checked separately and never counted as successful tool preparation.
    - For selected fixed-delay, Boolean repetition and Boolean delay-window families, state bits, assignments and operator/transition terms grow linearly with N; byte counts are measured separately. Dense N=16/32/64 controls remain. Compact N=1000/4096 cases must load/process in Yosys and complete actual SBY preparation for representative directive kinds. The local-expression invariant of point 20 still holds. General nondeterministic/product sequences and HISTORY have no new linear-size guarantee.


22. **Selected-layout resource guard.** Before emitting temporal RTL, the public emitter checks the selected form's frontier evaluation work (letters, guard references and successor references), counting each replay in HISTORY and each configuration's emitted logic. It admits compact layouts using reachable per-age work; it never substitutes dense DIRECT cost for compact cost. Oversized forced forms and manually built oversized machines raise a resource error before large output is constructed. Existing admitted outputs are byte-identical. Small useful capacity controls exercise a holding exact-delay property under PDR, a deliberately one-cycle-late implementation under BMC and a reachable nonvacuous cover with free overlapping requests. The latter two reach their hand-derived decision sample; preparation-only checks remain separately identified.

23. **Sparse attempt resource boundary.** The profiled `a[*1:2044] |-> (b or nexttime c)` completes compilation under the default work limit. Its selected emitter rejects the default 200000-reference allowance before RTL generation; raising only that allowance admits emission. This is a resource-policy boundary, not a successful proof or tool preparation.

**Scheduling.** Small emission-route controls remain in default; the larger strong unbounded configuration route requires `--extended` or `--slow`. Full trace/expression stress cases keep their existing `slow` classification and assertions.

The previous small named tool matrices are now split into default smoke parameters and `extended` variants; parameter values, case IDs, checks and expected statuses are unchanged. Default retains both compact forms, canonical/configuration/attempt monitors, L1/L2 liveness controls and fairness controls. Full table sweeps remain `slow`.

Broader native assertion/cover/expression checks use `extended` where another small default monitor control exercises the same integration path. Hand-derived temporal trace fixtures still run in default; full native tool capability checks are in the middle tier.

21. **Default representatives of the slow-table rules** (mutation campaign). Five trace cases run through the monitor in the default tier as in point 1: the swap of `not` (`not_fails_at_the_first_match`), the first match of a cover (`cover_counts_the_first_match_of_each_attempt`), the `$past(e, n)` gate (`past_depth_two_antecedent`), the first sample of a `$past` antecedent and consequent (`past_antecedent_does_not_hold_at_the_first_sample`, `past_consequent_fails_at_the_first_sample`) and the first sample of `$rose` and of `$fell`/`$stable`/`$changed` (`rose_at_first_sample_uses_x_default`, `first_sample_fell_stable_changed`). Two per-attempt cases with `disable iff` (`disable_in_nested_implication`, `disable_at_the_decision_sample`) and one hand-derived variant (`a |-> (b |-> c)`, `rst` high at the sample where the attempt would be true: no success there, success at the next) run through the per-attempt monitor. `u <= v` is checked on a fixed hand-derived trace (equal operands hold). Four expressions of point 4 run by default (`unsigned_compare`, `signed_negative_constant`, `rose_of_vector_lsb`, `stable_vector`): an operator emitted wrongly, or a sampled-value function reading the unconstrained history register at the first sample, fails them. The full tables stay `slow`.
24. **`initial` procedures** (IEEE 1800-2017 16.14.6, `docs/semantics.md` section 6). The cases of `initial.trace` (`procedure: initial`, hand-derived) run as in points 1 and 2: the monitor of a directive in an `initial` block has `FirstSample` (`!valid`, the per-property init bit that `disable iff` never clears) in its enabling condition, so only the attempt at the first tick can fail or succeed. The full set runs under `slow`; fast representatives run by default (`test_initial_directives_through_the_monitor`: one attempt, a cover reporting only the first attempt, `$past` at the first tick, an `if` true and false at the first tick, a `disable iff` true at the first tick). The mutant `initial-first-sample-always-true` (FirstSample emitted as `1'b1`) fails them.
25. **Monitor header**. After the `// source:` line, every monitor states its effective sampling clock (`// clock: posedge <signal>`) and, when the directive has a disable condition, `// disable iff: <condition>` (defaults applied, signals named as in the monitor's scope). When the caller passes the assertion's text as written, `// as written: <text>` comes between them (one line). These lines are comments: they never change the monitor's behaviour (checked with the rewrite area, `rewrite/CONTRACT.md` point 20).

26. **Condition wires name their source** (readability). The `assign` line of every condition wire `e<N>` of a monitor ends with `  // <text>`, where `<text>` is the wire's expression as written over the design's signal paths (`(!m.previous_level)`, `(m.level && (!m.previous_level))`; the first-sample condition is written `first sample`). The text is on one line (whitespace folded) and at most 80 characters: a longer one is cut to 77 characters followed by `...`. These are comments: the monitor's behaviour is the same with or without them (checked by the existing behavioural tests of this area, and by the output dump, which differs only in these comments).
