# Source rewriting contract

These tests cover `sva2yosys.rewrite`: `syntax_items` over the exporter's `sva2yosys_syntax` inventory, and `rewrite`. The design is in `docs/architecture.md`, *Source rewriting*.

Each case compiles its sources with Slang (`export_texts`), converts them, reads the inventory, and rewrites with a designated set of verification files. The sources are the checked-in `fixtures/` designs for the full cases and small inline texts for the error cases.

## Output

`restrict property` is rewritten through the existing formal assumption path
(IEEE 1800-2017 16.14.4). Boolean and temporal restrictions constrain assertions;
removing the restriction permits a counterexample. Supported strong restrictions
provide fairness only in the live task, and do not establish a stronger liveness
claim. Reachable covers check that finite restriction controls are satisfiable.
Witness-class strong restrictions remain located rejections. This is formal
lowering, not restrict's ignored-in-simulation behavior.

1. **Verbatim preservation.** A verification file's output has as many lines as the input. Outside the replaced and removed ranges, it equals the input character for character, and every character keeps its line. This holds for any UTF-8 text, including non-ASCII characters before an edit.
2. **Assertions become monitor instances.** The output files are listed in input order.
   - Each concurrent assertion of a verification file becomes exactly one instance `__sva2yosys_p<N> __sva2yosys_i<N> (...)`, at the line where the assertion started.
   - `N` numbers the assertions in source order: verification files in input order, then offset.
   - The instance text is exactly `__sva2yosys_p<N> __sva2yosys_i<N> (.clk(<clock>), .i0(<s0>), …, .fail(), .success());`. Each `<…>` is the signal's simple name (the last component of its hierarchical path), connected in `monitor_ports` order; `fail` and `success` are left open.
   - The monitor is generated from the assertion with its signals renamed to these simple names and without an instance path, so it does not depend on the instance.
   - The monitors file holds one module per `N`, equal to `monitor_module` of that localized assertion's machine.
   - A procedural assertion (inside an `always` or an `initial` block) cannot hold a module instance. Its statement is replaced by `;` (a null statement, so `if (c) assert …;` stays valid) followed by its line breaks, and its instance (or `generate if` chain) is inserted right after the outermost enclosing procedural block, on that block's last line. The instance connects names visible in the block's enclosing scope. An always block that is the unbraced body of a generate construct is an error (the instance would leave its scope).
3. **Declarations are removed.** `property` and `sequence` declarations, clocking blocks (default or not; `read_verilog` reads none) and `default disable iff` declarations of verification files are replaced by their line breaks only.
4. **Binds are lowered.**
   - A module bind in a verification file is removed (whitespace, same newlines).
   - Its instantiation text, as written, is inserted as new lines just before the line of `endmodule` of the target module.
   - A design file containing a target module is output as a copy that differs from the input only by the inserted lines: removing them gives the input back. Design files without a target are not output.
   - The same applies when the target module is in a verification file.
5. **Instances share a monitor, or get one each.** An assertion elaborated in several instances, or in several iterations of a generate loop, is spliced once when all instances give the same monitor and connections.
   - The parameters, type parameters and genvars *visible at the assertion* are those of its scope and the enclosing ones that are declared before it in its compilation unit (includes expanded). Per name, the innermost such declaration counts; one declared after the assertion hides nothing there. A declaration whose order relative to the assertion is unknown (another compilation unit) makes the name not comparable, which is an error as below. When there are none, every instance must give the same monitor (otherwise it is an error), and the site is spliced once as above.
   - Otherwise the site becomes a `generate if` chain that compares **every** visible parameter, not only those that differ: each branch `__sva2yosys_p<N>_g<k>` holds for exactly the value combinations seen in the instances of its variant, and instantiates that variant's monitor (`__sva2yosys_p<N>` when there is a single variant, `__sva2yosys_p<N>_v<k>` otherwise). A single variant is guarded the same way. A parameter whose declaration fixes no width (`parameter P = 1`, whose type comes from its value) is compared with its width (`$bits(P)`) and signedness too, since `P == 1'b1` also holds for `P = 8'b1`; Yosys then selects the monitor only for the observed type.
   - A final `else` branch `__sva2yosys_p<N>_unexpected` holds `always @* assert (1'b0)` (Yosys names it by its source position; labels are not scoped by generate blocks there). Should the module ever be elaborated with another combination of values, the proof fails instead of silently checking another instance's monitor.
   - It is an error when something visible cannot be compared: a parameter that is not integral (a string, real or type parameter; Yosys `read_verilog` cannot read `parameter string`), a parameter with an escaped name, or an interface port (its connected instance's parameters, as in `##(p.N)`, key nothing at the site), when the instances see different sets of parameter names, and when two instances with the same values need different monitors.
5a. **A property `and` gets one monitor instance per conjunct** (`__sva2yosys_p<N>_c<k>`, instance `__sva2yosys_i<N>_c<k>`), each asserting or assuming its own conjunct, together in one `if (1'b1) begin : __sva2yosys_p<N>_and ... end` block (one statement under an unbraced `if`/`else` or loop). A `cover` of a property `and` is never split: it gets one per-attempt monitor (point 7a). The wrapper is `if (1'b1) begin : … end else begin end`: its own empty `else` keeps an enclosing unbraced `if`'s `else` with that `if` (checked by elaboration).
6. **SVA in design files.** Design files are never translated. Every SVA item in a design file, or in a file included by one, is reported with its location: an assertion (elaborated or not, accepted or rejected by the converter), a declaration, a clocking block, a `bind`, a checker. Such items would reach Yosys unchanged (`read_verilog` applies its own SVA semantics, if any, and ignores `bind`), so each is an **error** by default. With `design_sva=WARNING` (the CLI's `--allow-design-sva`) each is a warning instead, and the file is left alone. Design assertions are not numbered.
7. **Deterministic.** Rewriting twice gives identical output.
7a. **Per-attempt monitors.** A directive that compiles to the per-attempt machine (`temporal.compile.compile_monitor`) is spliced like any other: its monitor module carries the `// form: attempt` header, is recorded with the direct form (whatever the strategy), gets no equivalence job, and no concurrent SVA is left (e.g. `a |-> (b |-> c)`).

## Unbounded antecedents and `always`

12. **Unbounded antecedents and unbounded `always` check under SBY**, in the setting of point 10 (fast cases by default, every case and its counterpart under `slow`):
    - `assert property (a ##[1:$] b |-> c)` proves under `assume property (b |-> c)` and fails (BMC, step 1) without it; `assert property (always a)` proves under `assume property (a)` and fails at step 0 without it; `assert property (a |=> always b)` fails at step 1;
    - `a[*2:$] ##1 b |=> c` proves under `assume property (a ##1 a ##1 b |=> c)` and fails (step 3) under `a ##1 b |=> c`; `a ##1 b[->2] |-> c` and `a ##1 b[=2] ##1 c |-> d` prove under `assume property (b |-> c)` / `(c |-> d)` and fail unassumed (steps 2 and 3); `always [1:$] (a |-> ##1 b)` proves under `assume property (a |-> ##1 b)` and fails (step 2) without it; `a |-> always b` proves under `assume property (b)`;
    - `disable iff (rst)` masks the unbounded antecedent (the property proves under an assumption that only excludes failures outside `rst`); an `assume` of an unbounded antecedent or of `always a` constrains the design;
    - whatever `--strategy` says (`auto`, `window`, `history`), the monitor of an unbounded antecedent is the direct one and gets no equivalence job.
    - A `cover` of an unbounded antecedent or of `always`, and an unbounded consequent, are errors located at the directive (`unbounded ranges`, `unbounded 'always'`).

## X-checks

9. **Skipped X-checks are removed.** A directive the converter skips (`Conversion.skipped`, `docs/semantics.md` §8a: `$isunknown` evaluated as 0 leaves nothing to check) gets no monitor and no instance. Its statement is replaced by a generate block `if (1'b1) begin : __sva2yosys_x<n>_skip /* sva2yosys: skipped (X-check): <reason> */ end else begin end` followed by its original line breaks (everything else keeps its line, point 1), so that an unbraced generate body (`if (1) x: assert ...; else ...`, a loop body) stays valid; a procedural one is replaced by `;`, the comment and the line breaks, so `if (c) assert ...;` stays valid. **Parameters.** A skip is decided per elaborated instance, after parameters have folded (`if (K) !$isunknown(a) else b` checks nothing only for `K = 1`). When parameters or genvars are visible at the site, the comment block is selected by a `generate if` on the values its instances had, and every other combination gets a failing branch (`always @* assert (1'b0)`), as for monitor sites (point 5): elaborating the rewritten module with `K = 0` fails under SBY instead of losing the assertion. `Rewrite.skipped` has one `note` diagnostic (located at the directive) per skipped site, in source order, however many instances the site has. No concurrent SVA remains in the file.
    - Directives with checks left are spliced as usual; their `ConversionWarning`s become `Rewrite.warnings`, once per site, located at the first `$isunknown`.
    - A site whose instances disagree (some skipped, some kept) is an error located at the site.
    - Under SBY (fixture `xchecks`: a counter with X-check asserts, an assume and a cover, and the real assertion `en && cnt != 4'd15 |=> cnt == $past(cnt) + 4'd1 && !$isunknown(cnt)`), the rewritten design proves, the mutant fails at step 8, and the monitors file has exactly the monitors of the real assertions. The skipped assume constrains nothing: a cover of `cnt == 4'd15` is reached at the same step as without the X-check directives.

## Errors

8. Each of these is an error with the given location. An error produces no output:
   - an assertion in a verification file that the converter or the compiler rejects (the rejection's message and location, which may be inside the assertion), including a `cover` that the cover rule rejects (`docs/semantics.md` §9.5, e.g. `cover property ((a |-> b) or (c |-> d))`), located at the directive;
   - an assertion in a verification file that was not elaborated (an uninstantiated module or generate branch);
   - an assertion produced by a macro expansion;
   - a procedural concurrent assertion that cannot be lowered (`docs/semantics.md` §6), `expect` or `cover sequence` (converter rejections);
   - a name that means something else at the assertion (e.g. a property declared at module level and asserted inside a generate block that redeclares one of its names);
   - any SVA item (assertion, declaration, clocking block, bind, checker) in a file included by a verification file;
   - an assertion inside an interface (or program);
   - instances of one assertion giving different monitors that their integral parameters and genvars do not tell apart (e.g. a string parameter);
   - a signal that is not a plain identifier of the assertion's scope or an enclosing scope of the same instance (e.g. a package variable);
   - a `checker` declaration in a verification file;
   - an instance bind (`bind m: i1 …`, `bind top.u …`), or a bind produced by a macro (an undeclared or duplicate target, or a bind into an interface, is already a Slang error);
   - two output files with the same base name, or one named like the monitors file.

## End to end (opt-in, `SVA2YOSYS_SBY`)

9. **Rewritten designs check under SBY.** For the `counter` fixture, the output is read with `read_verilog -formal -sv`: untouched design files, design copies, rewritten verification files and the monitors file. The bound properties then behave as follows:
   - against the correct design, the assertions prove (`abc pdr`) and the cover is reached;
   - against the mutant design (it skips one count), BMC fails, and the reported step is the earliest sample at which any input sequence can violate the property.
   - a procedural `if (en) assert property (a |=> b)` proves against `b <= a & en` (only enabled attempts exist) and fails at step 1 against `b <= a & !en`.
   - procedural directives (free inputs `en`, `a`, `b`, `rst`, `sel`): an enabled `cover property (a |-> b)` is reached, and one enabled by a register that is never true is not; an enabled `assume property (a |=> b)` proves `en && a |=> b` but not `a |=> b`; in a `case`, a later identical item is never reached and `default` holds exactly when no item matches (a wrong `default` assertion fails); `disable iff (rst)` aborts the obligations of an enabled assertion when an assumption raises `rst` after each trigger, while the same assertion without `disable iff` fails.
10. **Per-attempt properties check under SBY**. A verification module with free inputs `a`, `b`, `c`, `d`, `e`, `rst`, whose assumptions are canonical monitors, is rewritten and checked; each per-attempt directive behaves as IEEE 1800 requires:
    - `assert property (a |-> (b |-> c))` proves under `assume property (a && b |-> c)` and fails (BMC) without it;
    - `assert property (not (a |-> b))` proves under `assume property (a && !b)` and fails when `a` is assumed low (a vacuously true implication makes `not` false);
    - `assert property ((a |-> b) or (c |-> d))` proves under `assume property (a |-> b)` and fails without assumptions;
    - `assert property (if (e) (a |-> b) else (c |-> d))` proves under `assume property (e && a |-> b)` and `assume property (!e && c |-> d)`, and fails with only the first;
    - `assert property (if (e) strong(a) else weak(b))` proves under `assume property (e |-> a)` and `assume property (!e |-> b)`;
    - `assert property (disable iff (rst) a |-> (b |-> ##1 c))` proves under an assumption that raises `rst` one sample after every `a && b`, and fails without `disable iff`;
    - `assume property (a |-> (b |-> c))` (a per-attempt assumption) makes `assert property (a && b |-> c)` prove;
    - `cover property ((a |-> b) and (c |-> d))`, `cover property (a ##[1:2] b |-> c)` and `cover property (not (a |-> b))` are reached, and are **not** reached when an assumption makes every attempt vacuous (`!a && !c`; `!a`; `!a`), so a vacuous success is never reported; `cover property (a ##[1:2] b |-> c)` is reached under `assume property (b)` but not when also `assume property (a ##2 b |-> !c)` (the consequent of one antecedent match fails, so the attempt is false although another match's consequent passes), while `cover property ((a |-> b) or (c |-> d))` is an error (cover rule).
11. **Temporal operators check under SBY**, in the same setting:
    - `assert property (a |-> nexttime [2] b)` proves under `assume property (a |-> ##2 b)` and fails (BMC, at step 2) without it; `assert property (nexttime [0] a)` fails at step 0 unless `a` is assumed;
    - `assert property (a |-> always [1:2] b)` proves under `assume property (a |-> ##1 b ##1 b)` and fails under `assume property (a |-> ##1 b)` alone;
    - `assert property (a |-> s_eventually [1:2] b)` proves under `assume property (a |-> ##[1:2] b)` and fails without it, at the step where the window closes;
    - `assert property (eventually [0:1] (c |-> d))` (per-attempt machine) proves under `assume property (c |-> d)` and fails when the assumptions force `c && !d` at two consecutive samples;
    - `cover property (always [1:2] b)` and `cover property (eventually [0:2] (a ##1 b))` are reached, and not reached when `b` is assumed low; `cover property (eventually [0:1] (((a ##2 b) or d) |-> c))` is an error (cover rule).
13. **Weak unbounded consequents check under SBY**, in the same setting: `assert property (a |-> ##[1:$] b)` proves with no assumption (a weak consequent cannot fail); `assert property (a |-> b[*1:$] ##1 c)` fails at step 0 unassumed and proves under `assume property (a |-> b ##1 c)`; `a |-> b[->2] ##1 c` fails at step 2; `always (a |-> b[*1:$] ##1 c)`, `a |=> b[*2:$]` and a `disable iff (rst)` variant (masked under `assume rst`, failing under `assume !rst`) behave likewise; an assumed unbounded consequent constrains. Every such monitor has the direct form and no equivalence job under any `--strategy`. `assert property (a |-> ##[1:$] 1'b0)` proves, and `assert property (disable iff (rst) a |-> ##1 1'b0)` is masked under `assume rst`, fails at step 1 under `assume !rst` and proves under `assume (!a)`. `strong(##[1:$] b)` as a consequent is an error.
14. **Weak `until` / `until_with` check under SBY**, in the same setting; every "proves" below is an IEEE implication (the assumptions are unconditional): `assert property (a |-> b until c)` fails unassumed and proves under `assume property (b)` (`b` always holds, so `b until c` cannot fail) and under `assume property (c)` (`c` holds at the start sample); `a |-> b until_with c` proves under `assume property (b)` and fails under `assume property (c)` alone (`c` without `b`); `a |=> b until c` and `always (a |-> b until c)` behave likewise; `assert property (b until 1'b0)` proves under `assume property (b)` and fails otherwise; an assumed `a |-> b until c` makes `a |-> b || c` provable, and an assumed `a |-> b until_with c` makes `a |-> b` provable. Every such monitor has the direct form and no equivalence job under any `--strategy`. `cover property (b until c)` is an error located at the directive (an `assume` of `s_until`, `s_until_with` or `not (b until c)` is accepted, point 18).
15. **Consequents that can never fail** (`docs/semantics.md` §9.6). A site whose `assert` / `assume` part cannot fail (`temporal.compile.never_fails_warning`) gets a `Rewrite.warnings` entry located at the directive, once per site and message, with the message of the CLI contract (point 16); the generated text is unchanged.

16. **Strong liveness**. `Rewrite.live` is true exactly when some monitor has a liveness part (`ConfigMachine.liveness` set). The monitor modules then carry their liveness logic inside `` `ifdef SVA2YOSYS_LIVE ``; the rewritten verification files are unchanged by it, and a strong unbounded `assume` needing a witness (several configurations) is an error with the liveness message (point 18). Under SBY the `prove` task (the ordinary read script) passes `assert property (a |-> strong(##[1:$] b))` when the safety part holds, and the `live` task (the read script with `-D SVA2YOSYS_LIVE`) fails it when the obligation can stay pending for ever.
17. **`not` of an unbounded sequence**. `Rewrite.live` is true exactly when some monitor has a liveness part: for `assert property (not (a until b))` and `not (a ##[1:$] b)` (strong after the negation) and not for `not strong(a ##[1:$] b)`. An `assume` of `not` of a weak sequence is accepted with one configuration (`not (a until b)`, point 18) and an error with the liveness message otherwise; an `assume` of `not strong(...)` is accepted and constrains the design. Under SBY (the setting of point 16), for `not (a until b)` and `not (a ##[1:$] b)` with an assumption fixing the inputs: `a && b` forever fails the `prove` task and passes `live`, `a && !b` forever passes `prove` and fails `live`, `!a` (the sequence dies) passes both; for `not strong(a ##[1:$] b)`, `not (a s_until b)` and `not s_eventually b` the `prove` task alone decides (`a && !b` forever passes, a match fails). `assert property (not (b until c))` is not an error (nor is the `assume`).
18. **Strong `assume` in the one-configuration class**. `Rewrite.live` is true for an `assume` with a liveness part (`assume property (a |-> s_eventually b)`, `a |-> b s_until c`, `not (b until c)`; false for `not strong(...)` and a weak assume). An `assume` needing a witness (`not (b ##[1:$] c)`, `a |-> strong(##[1:$] c)`) is a `RewriteError` with the liveness message. Under SBY (the setting of point 16), the `live` task (read script with `-D SVA2YOSYS_LIVE`) sees the assume's fairness constraint and the `prove` task does not: `assert a |-> s_eventually b` with `assume a |-> s_eventually b` passes both; `assert a |-> s_eventually (a && b)` with the same assume passes `prove` and fails `live`; `assert s_eventually (!a || b)` passes `live` with `assume not (a until b)` and fails it without.
    - **Cover warning.** When a run accepts an `assume` with a liveness part, every accepted `cover` gets a `Rewrite.warnings` entry located at the cover: `<name>: this cover's result ignores the fairness assumptions (strong assume) of this run: a reached cover is provisional, see docs/usage.md`, whatever the order of the directives; no other directive gets one, and a run without such an assume (only a strong `assert`, a weak or `not strong` assume) gives none. The monitors are unchanged.
    - **Never-fails hint.** The never-fails warning of a weak `assume` ends with `(a fairness constraint needs a strong assume, see docs/usage.md)`.


19. **Resource exhaustion.** The written directive is checked before lowering/splitting and each selected monitor form is checked before emission. Huge bounded canonical properties and oversized forced forms produce a located RewriteError rather than partial rewritten output. Admission uses actual compact work; ordinary accepted output is unchanged.

**Scheduling.** Named tool matrices retain small default controls and put their remaining parameters in `extended`. Every original parameter, assertion and expected result remains in the full `--slow` run; `--extended` includes the whole small matrix. Larger existing stress matrices remain `slow`.
20. **The original assertion is quoted in the generated code** (`test_rewrite_comments.py`). The text is the source range of the assertion item as written (statement label and closing `;` included), taken from the input text and never printed from the IR, with every whitespace run (newlines too) folded to one space.
    - **Instance site.** The instance text is followed by a space and a block comment `/* <text> */` on the same line (a `//` comment would swallow code that follows). `*/` inside the text is written `* /`. Point 1 still holds: the comment has no newline. A property `and` split into conjunct instances gets one comment, after all of them; an assertion in a procedural block gets it after the inserted instance.
    - **Monitor header.** After `// source:` the header has `// as written: <text>`, `// clock: <edge> <signal>` and, with a disable condition, `// disable iff: <condition>`; clock and condition are the effective ones (defaults applied), the signals named as at the site. Instances sharing a monitor give the text of the one site they share.
    - The commented output elaborates and proves as before.

21. **The parameter rule is shared with check mode**. The refusal of a site with a parameter that cannot be compared (`uncomparable_parameters`, point 17 of `slang_convert`) is made by the conversion, so a directive with such a parameter never reaches the rewrite; the rewrite keeps its own refusal as a guard, with the same text (`uncomparable_message`), for directives built another way. For every case of the area, check mode rejects exactly the directives for which generation fails with that message.

22. **Selection by the dependencies**. The `generate if` chain that selects the monitor of an elaborated instance compares only the parameters the monitor can depend on (`Directive.dependencies`; every visible parameter when it is `None`), each with its value and implicit type as before; a parameter outside the set is not compared and cannot make the elaborations differ. Instances that agree on the compared values must give the same monitor and the same connections: when they do not, the rewrite is an error ("the values do not determine the variant"), which catches a dependency the analysis missed among the instances seen. A module elaborated with an unseen combination of compared values still fails loudly through the final `else` branch; an unseen value of an uncompared parameter shares the monitor of the others, which is sound because the monitor cannot depend on it. The refusal of a non-comparable parameter (point 21) applies to the compared parameters only.

23. **Binds with the `slang` frontend**. `rewrite(..., frontend=YosysFrontend.SLANG)` keeps the `bind` statements of the verification files character for character (they are not blanked), inserts nothing into any target module, and so produces no design copy (`FileRole.DESIGN_COPY`) at all. The assertions are replaced by their monitor instances exactly as without the option, so the written verification files differ from the default ones only in the kept `bind` statements. The rules on binds that do not depend on the lowering stay: an instance bind (`bind top.u1 ...`) is refused as before (point 8). A directive with a liveness part is an error, with the message of `passes/frontend.py` (the same rule as check mode); no output is produced. With `VERILOG` (the default) nothing changes.

24. **A signal the monitor does not read** (found by the SVA IEEE corpus). A property can name a signal that the compiled monitor never reads, because the part that names it cannot match: `go |-> a[*0] ##0 b` (an empty match fused with `b` never matches, IEEE 1800-2017 16.9.2.1), so `a` is no port of the monitor. Check mode accepts such a directive, and so does the rewrite: the written file has the monitor instance with the ports it reads, and the monitor checks the property (here: it fails at the first sample where `go` holds). It is neither a crash nor a rejection.

25. **The liveness parts and the fairness assumption**. `Rewrite.live_monitors` lists, in order, the monitor modules of `assert` directives that have a liveness part (one per part of a property `and`); `Rewrite.fair` is set by a fairness `assume` (which has a liveness part but is not listed: it is switched on by `SVA2YOSYS_LIVE_FAIR`). Behaviourally, with SBY `live` (suprove) and only one part switched on (`SVA2YOSYS_LIVE_<part>`): a part that cannot hold (`s_eventually (b && !b)`) fails and a part that holds (`s_eventually (b || !b)`) passes, whichever comes first in the source; a part that holds only under a fairness `assume` (`a |-> s_eventually b`) passes with `SVA2YOSYS_LIVE_FAIR` and fails without it, and the failing part still fails with it.
