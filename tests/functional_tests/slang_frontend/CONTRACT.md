# Slang frontend contract

These tests cover `sva2yosys.slang.export`: elaborating SystemVerilog with pyslang and exporting every concurrent assertion as JSON in a subset of Slang's native `--ast-json` format. The format is described in the module docstring of `src/sva2yosys/slang/export.py`. pyslang is a runtime dependency, so these tests always run, except point 15, which needs the slang executable (`SVA2YOSYS_SLANG`).

## Fixtures

- `fixtures/basic_forms.sv`: one module with every basic assertion form: implications, delays, ranges, repetition, sampled-value functions, `disable iff`, `##0`, assume, cover.
- `fixtures/defaults_and_decls.sv`:
  - `default clocking` and `default disable iff`;
  - a named sequence and property with arguments;
  - a parameter `N` used as a delay bound;
  - two instances with `N = 3` and `N = 5`.
- `fixtures/checker_bind_hier.sv`: a checker with arguments, a `bind`, and a hierarchical reference.
- `fixtures/expressions.sv`:
  - every exported expression kind, a folded constant, and a user function call;
  - an `iff` clock, and a generate-loop array;
  - an instance array of two identical instances;
  - two modules in one file whose `default disable iff` declarations shift lines (one spans two lines).
- `fixtures/expected/<fixture>.json`: golden exports. Paths in them are relative to `fixtures/`, because the tests run with `fixtures/` as working directory.

## Contract

The support-table audit fixture `fixtures/support_boundaries.sv` distinguishes
Slang elaboration/export from converter support. Its restrict directive, negative
and iff clocks, both clocks of a multiclock implication, gated past arguments,
nested sampled calls, triggered sequence body and package-defined sequence/property
bodies must be retained with source locations. First-match is a located unsupported
export stub; clocked past retains located EmptyArgument/ClockingEvent stubs.
Successful export of these records makes no claim that they can be lowered.

1. **Envelope.** The document is `{"format": "sva2yosys-slang-ast", "formatVersion": 2, "slangVersion": <pyslang version>, "assertions": [...], "sva2yosys_syntax": [...], "sva2yosys_includes": [...], "sva2yosys_packages": [...], "sva2yosys_packageUses": [...]}`.
2. **One record per assertion per instance.**
   - Every concurrent assertion of every elaborated instance (including checker instances and bound instances) produces exactly one record.
   - Records are ordered by `scope`, then source position.
   - Uninstantiated code produces none.
3. **Record fields.** Each record has:
   - `kind` = `ConcurrentAssertion` and `assertionKind` (`Assert`, `Assume`, `CoverProperty`, …);
   - `name` (the statement label, or `""`);
   - `scope` (hierarchical path of the enclosing instance or generate scope);
   - the six source-range keys;
   - `propertySpec`;
   - `sva2yosys_procedural`, `sva2yosys_clock` and `sva2yosys_defaultDisable`.
4. **Native encoding.** Nodes use Slang's `kind` names and keys as listed in the module docstring (e.g. `strong(s)` is `{"kind": "StrongWeak", "strength": "Strong", "expr"}`). Enumerations use Slang's enumerator names. An unbounded range maximum is `"$"`.
5. **Golden exports.** The export of each fixture equals its golden file exactly. Golden files change only through a deliberate update (`SVA2YOSYS_UPDATE_SNAPSHOTS=1`), which shows up as a diff.
6. **Per-instance folding.** In `defaults_and_decls.sv`, the delay of `s_resp(g, 1, N)` is `[1:3]` in `top.u3` and `[1:5]` in `top.u5`.
7. **Arguments are substituted.** Inside an `AssertionInstance` body, a formal argument resolves to the actual: `NamedValue` with `sva2yosys_path` `top.u3.req`.
8. **Default clocking.**
   - For an assertion without an explicit clock in a scope with `default clocking`, `sva2yosys_clock` is the default clock (`SignalEvent`, `PosEdge`, `clk`).
   - For an explicitly clocked assertion, it equals the explicit clock, including an `iff` condition.
   - Every instance gets its own clock, with its own instance paths, including repeated identical instances.
     - Slang's analysis reports such an assertion for only one of the instances. The others take its clock with the instance path rewritten.
     - This is allowed only when their exported properties are identical under the same rewrite; otherwise export fails with `SlangError` (`InconsistentInstanceAnalysis`).
9. **Default disable.** It is resolved for any source text, including non-ASCII characters before the declaration. A `default disable iff` in an included file or produced by a macro raises `SlangError` (`UnsupportedDefaultDisable`): the probe cannot place it, and losing it would change the assertions.
   - In a scope with `default disable iff (e)`, `sva2yosys_defaultDisable` is `e`, bound by Slang in that scope: `!rst_n` is a `UnaryOp` `LogicalNot` of `NamedValue` `top.u3.rst_n`.
   - Without one, it is `null`.
   - An explicit `disable iff` stays in `propertySpec`; the exporter does not decide precedence.
   - Source positions inside the default disable expression refer to the original text, even when the declaration spans several lines or another declaration earlier in the same file changes line numbers in the probe.
10. **Procedural assertions.** `sva2yosys_procedural` is `true` only for assertions written inside a user procedural block (e.g. `always`). Such a record also has (`docs/semantics.md` §6):
    - `sva2yosys_procedureKind`: `"always"` (an `always` or `always_ff` block) or `"initial"` (an `initial` block, IEEE 1800-2017 16.14.6: the directive has one evaluation attempt, at the first tick of its clock); every other block kind (`always_comb`, `always_latch`) is `"always"` too, with a `sva2yosys_procedureIssue`;
    - `sva2yosys_procedureClock`: the block's event control when it is a single `SignalEvent` (`always @(posedge clk)`, `always_ff`, `initial @(posedge clk)`), else `null`. An `always` block without it is an issue; an `initial` block without it is not (the assertion's own clock, or `default clocking`, applies, per 16.14.6 and 16.16);
    - `sva2yosys_enable`: the conditions on the path from the block to the assertion, outermost first: `{"kind": "If", "expr", "negated"}` (the `else` branch is negated) and `{"kind": "Case", "expr", "items": [Expression, …], "negated"}` (holds when `expr` equals one of `items`; a `case` item gives one entry for its own expressions and, if earlier items exist, a negated one for theirs; `default` gives a negated entry for all items);
    - `sva2yosys_procedureIssue`: `null`, or why the assertion cannot be lowered: the block kind (`always_comb`, `always_latch` …; Slang itself rejects an assertion in a `final` block) or, for an `always` block, its event control (an `initial` block is accepted with no event control, or with a single clock edge without `iff`; any other timing control, such as a delay or an event list, is an issue), a statement on the path other than `begin … end`, plain `if`/`else` and plain `case`, a statement of the block that may not fall through in zero time (e.g. `disable`, a delay, a loop), or a signal of the enabling condition that is not stable at the edge (with its name and the reason; `docs/semantics.md` §6: e.g. written by a blocking assignment in a clocked block or in a block triggered by another event, combinational, a continuous assignment, the clock). For an `initial` block the clock against which stability is judged is the block's event control, else Slang's semantic leading clock of the assertion (explicit, or `default clocking`).
    - An assertion in an `initial` block is exported exactly like one in an `always` block, with the same path rules except that a path condition (`if`, `else`, `case`) is an issue ("a condition around a concurrent assertion in an initial procedure is evaluated when the procedure runs at time 0, not at the assertion's first clock tick (IEEE 1800-2017 16.14.6.2); not supported: ..."), as are loops, `fork`, delays and statements that may not fall through; its `sva2yosys_clock` is the clock Slang resolves: explicit in the assertion, inferred from a single event control of the `initial` block (16.14.6), or `default clocking`; it is `null` when there is none.
11. **Unsupported nodes are marked, never dropped.** A node kind outside the exported set appears as `{"kind": <name>, "sva2yosys_unsupported": true, <range>}`.
12. **Errors.** Sources that don't compile raise `SlangError`. Its diagnostics carry severity, code, message and location (file as given, 1-based line and column), and its report is Slang's formatted text.
13. **An in-memory JSON boundary.** The export is returned in memory and nothing is written to disk. It contains only JSON values (dict, list, str, int, bool, None) and never pyslang objects. Converting it to JSON text and back gives an identical document.
14. **Export without probe.** `export_compiled` exports an already compiled design; every `sva2yosys_defaultDisable` is `null`.
15. **Native compatibility (opt-in, `SVA2YOSYS_SLANG`).** For every fixture, each exported record is a subset of a `ConcurrentAssertion` statement in the slang executable's `--ast-json --ast-json-source-info` output at the same source position. Concretely, every key that the record and its nodes carry (`kind`, `assertionKind`, the source range, and `propertySpec` recursively) is present in the native node with an equal value, except:
    - keys prefixed with `sva2yosys_`, which are ours;
    - `symbol`, where native Slang writes `"<address> <name>"` and we write only the name.

    Native Slang shares one body between identical instances, so several records may match the same native statement.
16. **Syntax inventory.** `sva2yosys_syntax` lists every concurrent assertion statement, `property`/`sequence` declaration, `default clocking` block or reference, `default disable iff`, `bind`, `checker` declaration and module declaration of every syntax tree, elaborated or not. Each item has:
    - its source range (excluding leading trivia, including a label and the closing `;`) and the matching offsets into the file text;
    - `sva2yosys_macro` for items produced by a macro expansion, which are located at the expansion;
    - the kind of the enclosing declaration, and the input file containing it (directly or through `include`);
    - for a module, its name and the offset of `endmodule`;
    - for a bind, the target as written, whether it is an instance bind (a scoped target or a target instance list), and the range of its instantiation;
    - for an assertion inside a procedural block, `sva2yosys_insertAt`: the offset just after the outermost enclosing procedural block, or -1 when that block is the unbraced body of a generate construct (else 0).

    A non-default clocking block is not listed.
17. **Identical instances with generate loops.** When Slang analyzes only one of several identical instances, each generate iteration of the other instances takes the clock of the same iteration (not of another iteration with the same source position).
18. **Visibility at the assertion.** Every `NamedValue` in a record (property, clock, default disable, and a procedural assertion's block event and enabling condition) carries `sva2yosys_visibleAtSite`: whether its name, looked up from the scope that contains the assertion, finds the same symbol. It is false for a name of a module-level `default disable iff` used inside a generate block that declares the same name.
19. **Includes.** `sva2yosys_includes` lists every `include` directive of every input file, nested ones too, with the input file being preprocessed, the path as written and the file Slang opened.
20. **Packages.** `sva2yosys_packages` lists every package declaration with its name and the input file declaring it (directly or through an include).
21. **Constant folding.** An expression that Slang did not fold but can evaluate as a constant in the scope containing the assertion (`ASTContext.tryEval`) carries `constant`, when the result is an integer without X/Z bits: e.g. `-1`, `N + 1` for a parameter `N`, `$bits(v)`. An expression reading a signal carries no `constant`; a literal with X/Z bits keeps Slang's own constant.
22. **Package uses.** `sva2yosys_packageUses` lists, per input file, each name the file uses before `::` (`import p::…`, `p::x`), once.

23. **Disable timing** (`docs/semantics.md` §7). Every record has `sva2yosys_disableIssue`: `null` when the `disable iff` condition in effect (an explicit one, else the scope's default) reads only constants, top-level inputs (also through plain port connections), input ports connected to an expression without calls of such signals (a continuous assignment of the expression, IEEE 1800-2017 §23.3.3; a constant connection reads nothing), and nets whose only driver is one zero-delay continuous assignment, without calls, of such signals; otherwise a message naming the first other signal (e.g. a register), since it may change at the clock edge. The same holds in every one of several instances with identical bodies, although Slang analyses the drivers of only one of them: their drivers are those of the analysed instance, read in their own instance, so each instance is judged by its own port connections. An input port that the module also drives itself is not followed to its connection, in every instance.
24. **Default sampled values** (`docs/semantics.md` section 8). Every `NamedValue` carries `sva2yosys_sampledDefault`, the class of its default sampled value (IEEE 1800-2017 section 16.5.1): `"x"` for a 4-state net, and for a 4-state variable or port without a declaration initializer; `"known"` for a 2-state type (`bit`, `byte`, `shortint`, `int`, `longint`) and for a variable with an initializer.
25. **Conversion target type** (`docs/semantics.md` section 8). Every `Conversion` expression carries `sva2yosys_fourState`, a boolean: whether its target type is 4-state. A cast to a 2-state type turns X into 0 (IEEE 1800-2017 section 6.11.2), so the converter rejects it inside a sampled operand.
26. **Integral types**. Every expression node carries `sva2yosys_integral`: `false` when its type is not integral (unpacked arrays, `real`, `string`), else `{"width", "signed", "msb", "lsb", "dims"}`, read from the canonical type (a typedef is its target): `msb`/`lsb` are the bounds of the outermost packed dimension, else `width-1`/`0`; `dims` is the number of packed dimensions (each packed array counts one, an enum or a packed struct/union one flat dimension, `int`/`byte`/`integer`/`logic` none); a packed struct or union (innermost element) adds `"aggregate": true`. An enum without a base type is a 32-bit signed 2-state value (`int`). The key is never absent on an expression node (an absent key is an export error for the converter).
27. **Conversion kind and `inside`**. Every `Conversion` expression carries `sva2yosys_conversionKind`, Slang's `ConversionKind` name (`Propagated` for the conversion of an operand to the type of its context, which extends by the sign of the context's type, IEEE 1800-2017 11.8.2; `Implicit`; `Explicit` for a cast). An `inside` expression is `Inside` with `left` and `ranges` (the set items in order); a range item is `ValueRange` with `left` and `right`, and a `$` bound is an `UnboundedLiteral` node (unsupported). Slang converts the left operand and every item to one common type and writes those conversions; a literal with X/Z/`?` bits keeps its digits in `value` when it is not converted. Slang evaluates constant expressions before the converter sees them, so an `inside` is trusted by its position in two cases only. (a) *Assertion operand* (an allow-list): it is reached from a Boolean operand of an assertion (a simple sequence or property expression, a `disable iff` condition) through run-time operators only (parentheses, `?:`, concatenation, unary and binary operators, a nested `inside`, the first argument of `$past`, `$rose`, `$fell`, `$stable`, `$changed`, `$countones`, `$onehot`, `$onehot0`, `$isunknown`, `$signed`, `$unsigned`), not in a repetition range, and above that operand no argument or default argument of a sequence or property is crossed before an assertion statement or a sequence/property declaration; any other syntax on the way (a select, a replication, a cast, another call ...) makes it untrusted. (b) *Run-time design code*: it reaches a continuous assignment, a procedural block or a task without crossing a declaration, type or dimension (every syntax kind named `…Declaration`, `…DeclarationStatement`, `…Type`, `…Dimension` or `…DimensionSpecifier`: a procedural `localparam`, a `typedef` or enum value, a variable's width) or the width of a size cast, and without being inside an assertion (an immediate assertion in an `initial` block is design code; a port connection, parsed as a property expression, is not). Every other `inside` anywhere in the design (parameters and their overrides, `defparam`, declarations, generate conditions, functions, which may be constant functions, port connections) is looked up among Slang's typed expressions (the AST and the conditions of generate blocks; matched by source position) and every typed instance of it is exported, as an `Inside` expression, in `sva2yosys_constantInsides` of every record (the key is absent when there is none). One that is not found there (e.g. a default or actual argument of a sequence or property) makes every record carry `sva2yosys_insideIssue` (a message naming the file and line of the first one; the key is absent otherwise), and the converter rejects it.

28. **Parameter dependencies** (`src/sva2yosys/slang/dependencies.py`). Every assertion record carries `sva2yosys_dependencies`: the sorted names, among those of `sva2yosys_parameters`, that the monitor of the assertion can depend on, or `null` (unknown: every visible parameter counts). The analysis is **sound by construction**: a name is left out only if it provably cannot change the lowered property, the clock, the `disable iff` condition, the enabling condition, or the width and signedness of any signal the assertion reads; whatever it cannot classify makes the whole result `null`, never a smaller list. A name is in the set when it is (a) referenced in the bound expression tree of the assertion, including the expanded bodies of named properties and sequences, argument substitution, the clocking event, the default clocking and default `disable iff` that apply, and the enclosing procedural block; (b) found by a scan of **every identifier of the assertion's syntax** resolved in its scope, because folded constants (`##LP`, `[*N]`, a sequence argument `K`, a cast `W'(x)`, `$bits(T)`) are absent from the bound tree; (c) reached by the closure over each referenced symbol: the declared type syntax of a variable, net, port or formal (including the packed and unpacked dimensions of non-ANSI and ANSI ports), typedef and enum chains, a type parameter (which Slang represents as a type alias), and the syntax and body of a module-local function, property, sequence or `let`. The closure stops at an integer parameter (the rewrite compares its value and implicit type) but follows the syntax of its **explicit type** (`localparam logic [W-1:0] LP`: `$bits(LP)` depends on `W`), and records a type parameter. A package or `$unit` function or property cannot depend on a module parameter and adds only its arguments; a system function adds only its arguments. **Unknown (`null`)**: a hierarchical reference, an interface port or modport, a symbol of another instance, a compilation-unit parameter whose name at the assertion resolves to another declaration, a checker instance or an assertion inside a checker, a class name or class property, a name that is not in the visible list, and any symbol kind the analysis does not handle. The generate conditions that only decide whether the assertion exists are not dependencies. **Hidden (`sva2yosys_hiddenParameters`)**: a parameter or type parameter the assertion depends on whose name at the assertion resolves to another declaration (an inner generate block redeclares it): it is not among the visible parameters, so no comparison can key the monitor on it, and the conversion rejects the directive (point 17 of the `slang_convert` contract). Every soundness hole is a counterexample test: a later declaration that shadows an outer one, a parameter of the same name redeclared in an inner block, a parameter whose explicit type uses another parameter, a port declared in two places, a type reached only through a typedef chain, a localparam derived from a parameter, a function called with a folded argument, an enclosing `if`/`case` in a procedural block.
