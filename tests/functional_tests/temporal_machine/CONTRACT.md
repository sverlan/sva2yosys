# Temporal machine contract (Layer 2)

These tests cover `sva2yosys.temporal`: a directive is compiled into a canonical machine (`compile_directive`) and run by the test simulator (`support.simulate`, which only drives the product's `step`). The machine must agree with the independent reference evaluator (`support.reference`) on everything a monitor can observe. The per-sample step is defined in `src/sva2yosys/temporal/machine.py`; the semantics are those of `docs/semantics.md`.

The longest property searches (beyond the longest match; the slot bound) are marked `slow` and run only with `pytest --slow`.

## Observable surface

The machine merges antecedent attempts, so it keeps no per-attempt provenance. The comparison therefore uses what a monitor reports, sample by sample:

- **failures**: samples with a failure event (the reference's `failures`);
- **successes**: samples with a success event, i.e. a non-vacuous success, or the first match of a cover attempt (the reference's `successes`);
- **pending**: obligations still open after the last sample (the reference's distinct pending obligation starts).

The reference's per-attempt verdicts (`VACUOUS`, `PASS`, …) are oracle instrumentation and are not compared.

## Contract

1. **Trace tables.** For every case of `tests/functional_tests/reference_semantics/fixtures/*.trace` that is not `support: oracle`, the compiled machine's failures, successes and pending count equal the table, under the same rules as Layer 1 (failures are not compared for `cover`). A `scope: attempt` case is compiled with `compile_monitors`: it must give exactly one monitor. When it is a per-attempt machine, that machine's `fail` rows (not for `cover`), `pass` rows, `outcome` rows (outcome class only), `decided` rows and pending-attempt count equal the table, as in point 8. When it is the canonical machine (a `temporal.trace` case whose lowered property the canonical machine decides exactly, e.g. `assert property (always [1:2] b)`), its first failure equals the table's and every `fail` sample of the table is among its failures (`assert`/`assume`; the canonical machine reports per obligation, so a later obligation of an already false attempt may add failures), and for a `cover` its successes equal the `pass` row.
2. **Differential, every prefix.** For generated valid supported properties, a generated disable condition or none, and generated traces, for **every prefix** of the trace. Two trace families are used: short traces of 1–10 samples for any generated property, and traces longer than the property's longest attempt, with the duration computed independently in `support/ir_strategies.py`, so that the upper ends of ranges and repetitions and the last slot are reached:
   - the machine's failures and successes up to the prefix's last sample equal the reference evaluation of that prefix;
   - the machine's pending count after that sample equals the reference's pending count for the prefix.

   This checks that the machine decides online, never late and never by looking ahead. The generated properties are weighted towards hard cases: `##0` fusion, ranges containing 0, nullable repetitions, repetitions of concatenations, several antecedent endpoints, both implication kinds, sampled-value functions, constants and disable.
3. **Slot bound.** For every generated machine:
   - the consequent's longest automaton path has at most `slots + 1` letters. An obligation alive at age `slots + 1` would need a path of `slots + 2` letters, so this proves the bound structurally;
   - all-low and all-high traces of `slots + 2` samples run without a `MachineError`;
   - every trace over the property's signals up to a small fixed length runs without a `MachineError`. That the bound is also tight, i.e. some trace uses the last slot, is checked on hand-derived cases in `tests/unit_tests/test_temporal_step.py` (e.g. `##[1:5]`, `##[1:12]`). The bound is not tight in general: an unsatisfiable letter (`c ##0 !c`) can make the longest path unreachable, and in a repetition range (`b[*2:3]`) the longest path passes an earlier accepting letter, where the obligation is already discharged. Such slots are wasted state, not a correctness problem, and are left to later optimisation.
3b. **Property `and`.** A `PropAnd` has one machine per conjunct (`conjunct_directives`); `compile_directive` of the conjunction itself is an error. Trace cases marked `scope: first-failure` and generated pairs of properties are checked on the first failure of the OR of the machines only (up to and including the first failure), against the table and the reference evaluator.
3c. **Oracle-only cases are rejected.** A trace case marked `support: oracle` is outside what the pipeline supports: `validate_directive` raises a `CompileError` for it, and so do `compile_monitors` and `compile_attempt_machine`; no machine is built. (The oracle-only cases are covers that the cover rule of `docs/semantics.md` §9.5 rejects, and the cases of `unbounded.trace`, `liveness.trace`, `until.trace` and `lasso.trace` with unbounded constructs the pipeline does not support yet, rejected by validation: the message names "unbounded ranges" or "not supported yet". An unbounded antecedent and an unbounded `always` over the supported operands are not oracle-only: points 15-20.) A case with a `rejected-by: <fragment>` header is rejected by all three with a message containing that fragment, verbatim; point 8 then expects that fragment instead of the per-file message.
7. **Compilation boundary.** `compile_monitors` gives, for every directive the pipeline accepts whose parts the canonical machine decides exactly (`machine_exact`; every generated basic directive and every table case outside `attempts*.trace`), the machines `compile_directive` gives for each part of `conjunct_directives`, so their monitors are unchanged. Every other accepted directive gives per-attempt machines, one per part: for `assert`/`assume` one per conjunct of a top-level `and` (each conjunct canonical where exact), for a `cover` exactly one (never split). Every `scope: attempt` table case of `attempts*.trace` that is not oracle-only compiles to per-attempt machines only; a case of `temporal.trace` compiles to the canonical machine exactly when its lowered property is a sequence, `not s`, or an implication into one (for a `cover`, with a single-length antecedent), else to a per-attempt machine. Weak and strong forms of the temporal operators (`nexttime`/`s_nexttime`, `always`/`s_always`, `eventually`/`s_eventually`) compile to equal machines.

## Unbounded antecedents and unbounded `always` (`docs/semantics.md` §9.6, R1)

For `assert` and `assume`, the canonical machine decides an implication whose antecedent has unbounded parts (`##[m:$]`, `[*m:$]`, goto, nonconsecutive repetition) when the consequent is a bounded sequence or `not` of one, and unbounded `always [m:$] p` for an operand that is such a sequence, `not` of one, or an implication into one, at the top or as an implication consequent (lowered to one implication: `temporal/lower.py`). The antecedent automaton has loops; the machine step and the registered state are unchanged. `$` is never replaced by a bound.

15. **Differential, every prefix.** For generated unbounded antecedents (`ir_strategies.unbounded_directives`: `##[m:$]`, `[*m:$]`, goto and nonconsecutive repetition mixed with the bounded constructs, `and`/`intersect`/`within`/`throughout`/`or`, both implication kinds, `not` consequents) and unbounded `always` (alone, over a sequence, `not`, or an implication, and as an implication's consequent), as `assert` and `assume`, with and without `disable iff`, on generated traces, for every prefix: the machine's failures, successes and pending obligations equal the reference evaluation of the prefix (traces of 1-10 samples; 11-16 samples under `slow`). Every generated directive compiles to exactly one canonical machine.
16. **Exhaustive.** For a fixed list of unbounded properties (`a ##[1:$] b |-> c`, `a ##[0:$] b |-> c`, `a ##[2:$] b |=> c`, `a[*1:$] ##1 b |=> c`, `a[*2:$] ##1 b |-> not c`, `(a ##1 b)[*1:$] |-> c`, `a[*0:$] ##1 b |-> c`, `b[->2] |-> c`, `b[->1:$] |=> c`, `b[=2] ##1 c |-> d`, `b[=0:$] ##1 c |-> d`, `always b`, `always [2:$] not b`, `always [1:$] (a |-> ##1 b)`, `always (a ##1 b |=> c)`, `a |-> always b`, `a ##1 b |=> always [2:$] c`, `a[*1:$] |-> always (b |-> ##[1:2] c)`), every trace up to a per-property length (up to 3 samples in the default run, up to `12 / signals` samples under `slow` (at most 9); with `disable iff (d)`, with the extra signal counted, likewise) gives the results of point 15 (machine equal to the reference, no `MachineError`).
17. **Reachable letters.** In every state reached on generated unbounded properties and traces, the registered antecedent frontier is a subset of `antecedent_reach(machine)` and each obligation slot a subset of `slot_reach(machine)`.
18. **No per-attempt machine.** A property with an unbounded part (a `$` range, goto, nonconsecutive repetition, unbounded `always`/`eventually`, `until`) never reaches the per-attempt machine: `compile_attempt_machine` raises a `CompileError` for every generated unbounded directive, `compile_monitors` of them gives canonical machines only, and every table case with an unbounded part that is accepted compiles to the canonical machine (`attempt` scope tables with unbounded parts are not run through the per-attempt machine; points 8 and 9 expect the `CompileError`).
19. **Mutants are caught.** For six anchored properties (`x ##1 a[*1:$] ##1 b |-> 1'b0`, `x ##[1:$] b |-> 1'b0`, `x ##1 b[->3] |-> 1'b0`, `x ##1 b[=2] ##1 c |-> 1'b0`, `always [3:$] b`, `x |-> always b`) the machine equals the reference on traces in which each signal is all 1, all 0, 1 only at one sample or 0 only at one sample; and each deliberately broken construction is caught: `[*m:$]` built as `[*m:m+2]`, `##[m:$]` built as `##[m:m+2]`, the looping filler of `##[m:$]` without its self edge, the repeated operand's final letters without their edge back to its start, goto built as `b[*n]` (the samples between occurrences not skipped), and an antecedent frontier that is forgotten at every sample.
20. **Table cases.** The cases of `unbounded_antecedents.trace` (hand-derived: `a ##[1:$] b |-> c`, `a ##[2:$] b |-> c`, `a[*1:$] ##1 b |=> c`, `a ##[1:$] b |=> c`, `b[->2] |-> c`, `b[=2] ##1 c |-> d`, `always b`, `always [2:$] b`, `always [2:$] (a |-> ##1 b)`, `always (a |=> b)`, `a |-> always b`, `a |=> always b`, `a[*2:$] ##1 b |-> c`, with `disable iff` and `$past`), and the cases of `unbounded.trace`, `liveness.trace` and `lasso.trace` that are not `support: oracle`, pass through point 1.

## Weak unbounded consequents (`docs/semantics.md` §9.6, R2)

For `assert` and `assume`, an implication (`|->`, `|=>`; antecedent bounded or unbounded) whose consequent is a weak unbounded sequence (default strength, or `weak(...)`), a weak unbounded sequence as the whole property, and `always` / `always [m:$]` over those (flattened by `temporal/lower.py`) compile to the configuration-set machine (`temporal/configurations.py`): one register per reachable *configuration* (the complete consequent frontier of an obligation), merged only when identical. `$` is never replaced by a bound. Still rejected with their messages: `strong(...)` of an unbounded sequence, `not` of one, `s_eventually`, `s_until`/`s_until_with`, every `cover` with an unbounded part. No warning for consequents that can never fail is printed for these.

21. **Differential, every prefix.** For generated weak unbounded consequents (`ir_strategies.config_directives`: sequences mixing `##[m:$]`, `[*m:$]`, goto, nonconsecutive repetition with the bounded constructs and `or`/`and`/`intersect`/`within`/`throughout`, bounded or unbounded antecedents, both implication kinds, a sequence as the whole property, unbounded `always` over such consequents, explicit `weak(...)`), as `assert` and `assume`, with and without `disable iff`, for every prefix of generated traces: the machine's failures and successes equal the reference evaluation of the prefix, and "some obligation is live" equals "some obligation start is pending" (traces of 1-10 samples; 11-16 under `slow`). Every generated directive compiles to exactly one `ConfigMachine`.
22. **Exhaustive.** For a fixed list of properties (`a |-> ##[1:$] b`, `a |-> b[*1:$] ##1 c`, `a |=> b[->2]`, `a |-> b[=2] ##1 c`, `a |-> (b ##[1:$] c)`, `a ##1 b |-> c[*2:$]`, `a[*1:$] |-> b[*1:$] ##1 c`, `a |-> (b[*1:$] or c ##2 d)`, `always (a |-> b[*1:$] ##1 c)`, `b[*1:$] ##1 c` as a property, …), every trace up to a per-property length gives the results of point 21, with and without `disable iff`.
23. **Configurations.** Every state reached stays within `machine.configurations`; the machine raises no `MachineError`; entry 0 is the consequent's start frontier; the configurations are distinct and every one is reachable by the static construction from entry 0. Obligations in one configuration share one bit: hand cases with overlapping attempts in different configurations (the unbounded counterexample of `docs/strategies.md` Example 3: one obligation dies at a sample where another, in a different configuration, is alive) fail exactly at the reference's sample.
24. **Mutants are caught.** Merging non-identical configurations (the next frontier read as the union of the live frontiers), `$` read as a finite limit in the consequent, and a dropped configuration transition each make the differential/anchored comparison fail.
25. **Budget.** A property whose consequent has more than `Budgets.configurations` reachable configurations, or whose structural letter estimate exceeds the letters budget, is rejected with a `CompileError` naming the budget, quickly (time-bounded test), with a location through `compile_monitors` and the CLI.
26. **Constants (Annex F).** Superseded by points 29 to 33: an unbounded weak consequent with a constant-false condition is accepted and never fails there (`a |-> ##[1:$] 1'b0`), 4a's rejection rule and its message are gone.
27. **Dispatch.** A directive that the canonical machine decides exactly compiles to it (byte-identical monitors); an unbounded consequent never reaches the per-attempt machine (`compile_attempt_machine` refuses it) and never the slot machine; a `cover` and the optimised forms do not apply (`auto` selects `direct`; forced `window`/`history` are refused with a reason).
28. **Table cases.** The now-accepted cases of `unbounded.trace`, `liveness.trace`, `lasso.trace` and the new `unbounded_consequents.trace` (hand-derived, including `disable iff` and `$past`) pass through point 1 (failures compared as for the canonical machine) and through the generated monitors under SBY.

## Per-attempt machine (`docs/semantics.md` §9.4, §9.5)

`compile_attempt_machine` compiles any structurally valid property (it skips only the supported-shapes rules of validation, which are the cover rule and the operand count of `and`/`or`, and checks both itself) into an `AttemptMachine`, run by `support.simulate.simulate_attempts` (which only drives the product's `temporal.attempts.step`). The oracle is the per-attempt reference (`attempt_results`, `evaluate_attempts`). For an attempt started at `s`, the machine's root age `t - s` reports at sample `t` whether it is decided true or false and whether its nonvacuity is known true.

8. **Attempt tables.** Every `scope: attempt` case that the cover rule accepts runs through `compile_attempt_machine`: its `fail` rows (not for `cover`), `pass` rows, `outcome` rows (outcome class only: true, false, pending, disabled; nonvacuity is checked through `pass`), `decided` rows and `pending` count equal the table. A `support: oracle` case that the cover rule rejects is rejected by `compile_attempt_machine` with the cover-rule message; one with a `rejected-by` header, with its fragment (point 3c).
9. **Every other table.** Every trace case outside attempt scope also runs through the per-attempt machine: for `assert`/`assume` (and `scope: first-failure`) the first failure equals the table's, and for `cover` the `pass` rows equal the table. (Later failures are per obligation in those tables and per attempt in this machine, so they are not compared.)
10. **Differential, per root age.** For generated property trees (sequences, `not`, `and`, `or`, `if` with and without `else`, nested implications of both kinds, `nexttime [n]`, `always [m:n]`, `eventually [m:n]` in weak and strong forms, with small bounds including `[0]` and `[0:0]`), an optional disable condition and generated traces (short ones, and ones longer than `life(p)`), on the whole trace and on every prefix: every attempt's outcome and decision sample equal `attempt_results`; the failures equal `evaluate_attempts`. When the cover rule holds (`cover_problem(p) is None`), the nonvacuity at every true decision and the successes equal the reference (nonvacuous and known by the decision), and so does the nonvacuity at every false decision when `nv_at_false(p)` holds; otherwise, for a tree without `always`/`eventually`, the machine never claims nonvacuity that the reference does not know by then (with `always`/`eventually`, which the machine lowers to an implication whose nonvacuity is that of any offset rather than offset-ordered, it may, and so may its successes when the cover rule fails; the `success` output is consumed only by covers, which the cover rule restricts to where it is exact). No run raises `MachineError` (the lifetime self-check).
11. **Exhaustive.** For a fixed list of small trees (including `nexttime [2]`, `always [0:1]`/`s_always [1:2]`, `eventually [0:1]`/`s_eventually [1:2]` over sequences and implications, and the counterexample `eventually [0:1] (((a ##2 b) or d) |-> c)` as an assert), every trace over their signals up to length 4 gives the results of point 10.
12. **Hand cases.** A failure and a success of different root attempts in the same sample are both reported; two overlapping parent attempts whose consequent attempts start at the same sample stay separate (one fails while the other passes).
13. **Mutants are caught.** The tests of points 10 and 11 fail for four deliberately broken constructions: two root ages' state merged, nonvacuity forced to true (spurious successes), nonvacuity of consequent and branch attempts dropped (missed successes), and an implication combining its consequent attempts existentially instead of universally.
14. **Budgets.** A property exceeding a construction budget (letters, instances, registers, gates) is rejected with a `CompileError` naming the budget, before any unbounded work (a huge range is rejected by the letter pre-check). This holds on the dispatch path too: `compile_monitors` chooses the machine without iterating over any range, so a cover such as `always [0:1000000000] b` or `a ##[1:1000000000] b |-> c` is rejected at once. Bounded slot machines also have shared resource limits (points 76-78).
4. **Cover uses the same machine.** A `cover` directive compiles to the same machine as the corresponding `assert`. Its successes count each attempt once, at its first match.
5. **Independence.** The tests compute expectations only with the reference evaluator and the trace tables. They never use `bounds`, `automaton`, `compile` or `simulate` internals to build an expectation.
6. **Reachable letters.** In every state reached on generated properties and traces, each obligation slot of age `a` is a subset of `slot_reach(machine)[a - 1]`, and the registered antecedent frontier a subset of `antecedent_reach(machine)`. The code generator stores only those bits.

## Constants are evaluated at their own sample (`docs/semantics.md` §3)

A constant-false condition is a letter whose condition is false, held at no sample and refuting a partial match at its own sample only; the automaton keeps it (a guard on the constant's table entry). Only structural emptiness (no accepting letter reachable, an `intersect` of fixed lengths that never meet) is decided ahead of time. All three machines (canonical, per-attempt, configuration-set) and the optimised forms follow this one rule.

29. **Table cases.** `constants.trace` (hand-derived, run by every layer): the failure sample of every case equals the table in the canonical, per-attempt and configuration-set machines: `a |-> ##1 1'b0` fails one sample after `a` and a `disable iff` true at that sample disables the attempt (also as `assume`); `a |-> 1'b0` fails at `a`'s sample; `a |-> ##[1:$] 1'b0` and `a |-> ##[1:$] (1'b1[=1] intersect 1'b1[*2])` never fail; `disable iff (r) 1'b1[=1] intersect (a ##[1:$] b)` does not fail at sample 0; goto/nonconsecutive of a constant, a constant inside a loop, as the first and last letter, in `intersect`, `not`, `or`, `throughout`, an antecedent, a cover; `(a |-> ##1 1'b0) or (c |-> d)` in the per-attempt machine.
30. **Differential and exhaustive with constants.** The generators of point 2, 15, 21 and 10 produce `Const` 0 and `Const` 1 conditions at every position (constants in unbounded consequents are no longer excluded), so for every prefix the machines equal the reference, including the failure sample; the exhaustive lists include constants.
31. **Nothing depends on a constant before its sample.** For generated properties and traces, replacing a constant-false condition by a signal that is low at every sample of the trace changes no machine verdict (failures, successes, pending), and a machine's verdict at sample `t` equals the reference's on the prefix `0 … t` (point 2), so no failure is reported before the sample that refutes it.
32. **Mutant is caught.** A constant-false letter pruned ahead of time (the automaton dropping `Bool(Const 0)` and the paths through it) fails point 29 on a `disable iff` trace (`disable iff (r) a |-> ##1 1'b0` with `r` high at the next sample) and point 30.
33. **Monitors without a constant-false condition are unchanged.** For the properties of the trace tables and generated properties without a constant-false condition, the generated monitor text equals the recorded baseline (a stored sha256 per trace case in `fixtures/monitor_digests.txt`; the fixture header lists the reviewed updates for bounded expression emission and for compact DIRECT emission). A reviewed update of a hash is accepted only after the old and the new monitor pass an SBY equivalence proof for every changed case; the comparator checks the exact changed-case set, and every other stored hash is unchanged. The cases whose text changed because a constant-false condition is evaluated at its own sample are listed with a reason in the test and are exactly the ones with a written constant-false condition: the `fusion_empty`, `implication` and `not` cases with `1'b0`. The weak `until` cases (`until_machine.trace` and the promoted weak cases of `until.trace` and `lasso.trace`) have no stored digest.

## Weak `until` / `until_with` (`docs/semantics.md` §9.3, §9.6)

For `assert` and `assume`, a weak `p until q` and `p until_with q` with Boolean operands are the weak sequences `p[*0:$] ##1 q` and `p[*0:$] ##1 (p && q)` (`temporal/lower.py`, `until_sequence`), accepted wherever a weak unbounded sequence is accepted: as the whole property, as the consequent of `|->`/`|=>` (bounded or unbounded antecedent), under `always` / `always [m:$]`, and in the forms `nexttime`, bounded `always` and a property `if` without `else` lower to. They compile to the configuration-set machine. Still rejected with located messages: `s_until` / `s_until_with`, `not` of an until, an until under a shape that needs the per-attempt machine (`or`/`and` of non-sequences, nested implications), and every `cover` containing an until. `$` is never replaced by a bound.

34. **Table cases.** The weak cases of `until.trace`, `liveness.trace` and `lasso.trace` and the hand-derived cases of `until_machine.trace` (`a |-> b until c`, `a |-> b until_with c`, `a |=> b until c`, `always (a |-> b until c)`, a top-level `b until c`, `c` at the first sample, `b` false before `c`, `b` and `c` both false, `until_with` where `c` holds without `b`, overlapping attempts, `disable iff` at the deciding sample, `$past` operands in each position, constant operands) pass point 1.
35. **Differential, every prefix.** `ir_strategies.config_directives` also produces `Until` (weak, exclusive and inclusive, Boolean operands from `conditions()`, which include `$past`, sampled-value functions and constants) as the whole property, as an implication consequent (both kinds, bounded or unbounded antecedent) and under unbounded `always`: for every prefix of generated traces the machine's failures and successes equal the reference's (`evaluate()` maps every property to obligation shapes with its own `tests/support/reference/shapes.py`, written from `docs/semantics.md` and importing IR types only, never `sva2yosys.temporal`; the native per-attempt evaluator `evaluate_attempts` gives a second check of the first failure and of each attempt failure), as in point 21. A guard test asserts that `tests/support/reference` imports nothing from `sva2yosys.temporal`, `optimize` or `codegen`, and a mutant lowering `until` as `until_with` fails the comparison against `evaluate()` itself. Every generated directive compiles to one `ConfigMachine`.
36. **Exhaustive.** For a fixed list of until properties (`b until c`, `b until_with c`, `a |-> b until c`, `a |-> b until_with c`, `a |=> b until c`, `always (a |-> b until c)`, `always [1:$] (a |-> b until_with c)`, `a[*1:$] ##1 d |-> b until c`, `$past` operands, constant operands, `nexttime (b until c)`, `if (d) b until c`), every trace over their signals up to a per-property length gives the results of point 35, with and without `disable iff`.
37. **Law.** An `Until` and the written `weak(p[*0:$] ##1 q)` / `weak(p[*0:$] ##1 (p && q))` compile to equal machines.
38. **First-sample rule.** The rule runs on every condition the machine sees after lowering, including the generated `p && q`: a `$past` operand is gated as in a written sequence, in each position (`p` of `until`, `q` of `until`, `p` and `q` of `until_with`).
39. **Mutants are caught.** `until` built as `until_with` and the reverse; `p` required at the sample where `q` holds for plain `until` (`p[*0:$] ##1 (p && q)` for `until`); `[*0:$]` read as a finite limit: each makes the differential and the table cases fail.
40. **Rejections.** `s_until`, `s_until_with` and `not (p until q)` are strong after negation: accepted in an `assert` (points 54 and 62) and in an `assume` (they have one configuration, point 69); a `cover` containing an until and an until under `or`/`and` of non-sequences or a nested implication are rejected with a located `CompileError` (the message names `until`).

## Covers of unbounded sequences (`docs/semantics.md` §6, §9.6)

A `cover` is reachability: a match on known samples satisfies it, so an unbounded part needs no liveness. The configuration-set machine's `success` output (an obligation whose held frontier has an accepting letter is discharged) is exactly "some attempt first-matches at this sample": the obligation of an attempt is discharged at its first match (later matches of the same attempt are not counted), the obligations of different attempts are merged only when their complete configurations are identical, and identical configurations match at the same samples, so the merge never changes the per-sample success bit a cover consumes. `disable iff` clears the state and suppresses the output as for `assert`. `fail` is not consumed.

Accepted covers, judged on the property as written (`passes.validate.cover_unbounded`):

- a sequence property with an unbounded part (`##[m:$]`, `[*m:$]`, goto, nonconsecutive repetition, at any nesting) that is strong: the cover default (§16.12.2) or an explicit `strong(...)`;
- an implication (`|->`, `|=>`) whose antecedent is bounded and has a single match length (`min_length == max_length` over its non-empty matches; an empty match is ignored, as for bounded covers), and whose consequent is such a sequence property.

41. **Table cases.** The now-accepted `scope: attempt` cover cases of `unbounded.trace` (`cover_unbounded_delay`, `cover_unbounded_pending_finalizes_false`, `cover_goto`) and `lasso.trace` (`cover_defaults_to_strong`) lose their `support: oracle` header, and the new hand-derived `unbounded_covers.trace` passes through the reference (layer 1), the machine (point 1: the machine's `success` samples equal the table's `pass` row, exactly, not only as a superset) and the generated monitors under SBY. It covers `a ##[1:$] b`, `a[*2:$] ##1 b`, `b[->2]`, `b[=2] ##1 c`, `a |-> ##[1:$] b`, `a |=> b[*1:$] ##1 c`, overlapping attempts matching at the same sample (one success sample), attempts of different configurations, an attempt whose frontier dies (no success), the first match of an attempt only (a second `b` after the match is not counted), `disable iff` during a pending attempt, `$past` in the sequence and a constant-false condition (`cover property (a ##[1:$] 1'b0)` never succeeds).
42. **Differential, every prefix.** `ir_strategies.cover_config_directives` produces `cover` directives of strong unbounded sequences and of implications with a single-length antecedent into one (`|->`, `|=>`, optional `disable iff`): for every prefix of generated traces the machine's successes equal the reference's, and "some obligation is live" equals "some attempt of the reference is pending" (as for point 21). Every generated directive compiles to one `ConfigMachine`.
43. **Exhaustive.** For a fixed list of covers (`a ##[1:$] b`, `a[*2:$] ##1 b`, `b[->2]`, `b[=2] ##1 c`, `b[*1:$]`, `a |-> ##[1:$] b`, `a |=> b[*1:$] ##1 c`, `a ##1 b |-> c[*2:$]`, a nullable single-length antecedent `a[*0:1] |-> ##[1:$] b`, a `$past` condition, a constant-false condition), every trace over their signals up to a per-property length gives the results of point 42, with and without `disable iff`.
44. **Counted once.** Two attempts that reach identical configurations and match at the same sample give one success sample (the machine merges them), and two attempts in different configurations that match at the same sample give one as well; an attempt that has matched is not counted again at a later match.
45. **Mutants are caught.** Success reported when the frontier is merely alive (a pending obligation counted as a match); success counted for a non-first match (the obligation kept alive after its match); a multi-length antecedent accepted for a cover; a weak unbounded sequence accepted for a cover: each makes the differential, the table cases or the rejection tests fail.
46. **Rejections.** With a located `CompileError` (messages in `docs/usage.md`): an explicit `weak(...)` of an unbounded sequence (a weak property can hold on an infinite trace without a finite match, so a finite match does not decide what a cover counts); `until` and `until_with` (weak: the same reason; `s_until` stays "not supported yet"); an implication with an unbounded antecedent (R1) or with an antecedent of several match lengths, when the consequent is unbounded; and every other cover with an unbounded part (`always`, `s_eventually`, `not`, `or`, `and`, `if`, `nexttime`, nested implications).
47. **Dispatch.** A cover with a bounded part only keeps its machine (byte-identical monitors); a cover of an unbounded sequence never reaches the slot machine or the per-attempt machine (`compile_attempt_machine` refuses it); the optimised forms do not apply.
48. **Model sizes** (hand-derived, pinned by the tests; `configurations` + antecedent bits). `cover property (a ##[1:$] b)`: 2 configurations (`{a}` and `{loop, b}`), 0 antecedent bits. `cover property (a |-> ##[1:$] b)`: 2 configurations, 0 bits. `cover property (a |=> b[*1:$] ##1 c)`: 2 configurations (`{b}`, `{b, c}`) and 1 antecedent bit (the `##1 1` of `|=>`). `cover property (b[->2])`: 3 configurations (`{!b-loop, b}`, `{!b-loop', b'}` and the union of the two that the independent-guard construction also reaches). `cover property (a[*2:$] ##1 b)`: 3. `cover property (b[=2] ##1 c)`: 6.

## Consequents that can never fail (`docs/semantics.md` §9.1, §9.6)

`temporal.configurations.never_fails(machine)` is a sound, conservative analysis of a configuration-set machine: `True` proves that the machine never reports a failure, whatever the trace; `False` only means "not proved". Criterion: the step is monotone in the set of held letters, so an obligation in a configuration can fail iff it fails when only the letters without guards are held (no accepting letter, no successor); `never_fails` is `True` iff no configuration can fail that way, and a machine without configurations (empty consequent) can fail. It is `True` for `a |-> ##[1:$] b`, `a |-> ##[1:$] b ##1 c`, `a |-> ##[1:$] 1'b0`, `a |=> ##[1:$] b`, `always ##[1:$] b`, `##[1:$] b` as a property, `a[*1:$] |-> ##[1:$] b`; `False` for `a |-> b[*1:$]`, `a |-> b ##1 (c ##[1:$] d)`, `a |-> b[->1]`, `b until c` (hand-derived in `tests/unit_tests/test_configurations.py`). `temporal.compile.never_fails_warning(monitor, part, parts)` turns it into the warning message for the `assert` / `assume` parts (never for a `cover`, never for another machine), naming the conjunct when there are several parts.

49. **Soundness against the reference.** For generated directives the configuration-set machine accepts (`ir_strategies.config_directives`; parts with a liveness part are skipped, since they get no warning), whenever `never_fails` is `True` the reference evaluator (`support.reference.evaluate.evaluate_attempts`) reports no failure on any trace of the directive's signals up to a small length (exhaustively; a longer search is slow-marked). The share of `False` answers whose directive never fails on the short traces is reported (conservativeness), not asserted.
50. **Mutants are caught.** Treating every letter as held (the largest held set instead of the guard-free letters) and ignoring the empty-machine case each make the soundness test fail.
51. **No change to the monitor.** The warning is a report only: every generated monitor is byte-identical to the one generated without the warning (point 27, and the digest test of the constants area).


## Strong liveness for `assert` (`docs/semantics.md` §9.6)

A strong unbounded consequent of an `assert` is decided by the configuration-set machine for its safety part (a frontier that dies fails, as for a weak one) and by a liveness signal for its liveness part: "no obligation stays pending for ever". The liveness signal is chosen per machine (`temporal/liveness.py`, pure). These points pin the front end of that (lowering, acceptance, the machine's liveness kind, the witness step) and its verdict against the reference on infinite (lasso) traces, through the test-support liveness simulator (`support.simulate.liveness_fails`). The generated monitors and the SBY runs come in a later step.

52. **Liveness kind.** `ConfigMachine.liveness` is `None` for a `cover` and for a weak consequent (also a strong sequence under `cover`, 4d). For an `assert` whose consequent `SequenceProperty` is strong (after lowering) it is `Liveness.PENDING` when the machine has at most one configuration (`s_eventually b`, `a |-> s_eventually b`, `a |=> s_eventually b`, `b s_until c`, `always (a |-> s_eventually b)`) and `Liveness.WITNESS` otherwise (`a |-> strong(##[1:$] b)`, `s_eventually [2:$] b` (`m > 0` puts repetition letters before the loop), `strong(b[->2])`, `a[*1:2] |-> strong(c ##[1:$] b)`); hand-derived configuration counts pin each.
53. **Lowering.** `s_eventually [m:$] p` with `p` a Boolean or a bounded sequence lowers to `strong(1[*m:$] ##1 p)` (16.12.13: `p` starts at an offset `k >= m`; for `k = 0`, `empty ##1 p` is `p` at the first sample, 16.9.2.1; same matches as `1 ##[m:$] p`, but for `m = 0` the start frontier is a fixed point, so these are pending-bit machines), and `p s_until q` / `p s_until_with q` to the strong sequence `p[*0:$] ##1 q` / `p[*0:$] ##1 (p && q)` (16.12.12); every other `s_eventually` (property operand, unbounded operand sequence, weak form) stays as written and keeps its rejection message. The reference evaluates these operators natively and never uses the product's lowering (`tests/support/reference` imports nothing from `sva2yosys.temporal`; guard test of point 35).
54. **Acceptance.** For an `assert`, a strong unbounded sequence is accepted in exactly the positions a weak one is (the whole property; the consequent of `|->` / `|=>` with any antecedent that the machines accept; what `always`, `always [m:$]`, `nexttime`, bounded `always` and property `if` lower to). For an `assume` it is accepted when its configuration machine has at most one configuration (point 69), and otherwise rejected by the compiler (`compile_monitors`, not by validation) with a located message containing `a strong unbounded property (liveness) in 'assume'` (point 70). `cover` is unchanged. Unbounded weak `eventually` and `s_until` with a non-Boolean operand keep their messages. (`not` of an unbounded sequence is accepted, point 62.)
55. **Witness step** (`liveness.witness_step(machine, frontier, events, pick, elapsed, raw)`, given the `StepEvents` of `configuration_step` for the same sample; conditions gated as there: a condition with past depth `d` does not hold while `elapsed < d`). `events.disabled` gives `None` (idle). A busy witness (`frontier` not `None`) takes the held letters of its frontier: an accepting held letter gives `None`, no successor gives `None` (death is reported as a failure by the configuration machine), otherwise the successor set; it never picks a new obligation in that sample, even when it becomes idle there (no re-pick in the sample the witness is freed). An idle witness picks only when `events.triggered` and `pick` and the machine has configurations: it starts from the start frontier (`configurations[0]`) and the obligation is evaluated at its trigger sample, as above. Hand-derived cases cover each rule, with `disable iff` and `$past`.
56. **Liveness simulator.** `liveness_fails(machine, lasso)` decides, exactly and by cycle detection (never a guessed bound), whether the liveness check fails on the infinite trace of a `Lasso`: PENDING, the pending signal ("some obligation is live after the sample", `bool(state.live)`) is 1 at every sample of the repeated cycle of (canonical position, `ConfigState`); WITNESS, for some launch sample `p` (a sample at which `configuration_step` reports `triggered`) the witness run that picks only at `p` is busy at every sample of its repeated cycle of (canonical position, frontier). Unit tests (`tests/unit_tests/test_simulate.py`) pin its verdict on hand cases and on the repeated-cycle logic.
57. **Verdict against the reference, table cases.** For every accepted `assert` lasso case (`lasso.trace`, `strong_liveness.trace`, the strong case of `constants.trace`) whose machine has a liveness kind: (a) when no attempt of `lasso_attempt_results` is FALSE at a finite sample (every FALSE attempt is undecided: `inf-decided` is `.`), `liveness_fails` equals "some attempt is FALSE in the limit", and the configuration machine reports no failure on the unrolled trace; (b) otherwise the configuration machine reports a failure at a finite sample, at or before the earliest finite FALSE decision of the reference, on the unrolled lasso, and `liveness_fails` is not compared (one attempt can fail at a finite sample while another of its consequent obligations stays pending for ever: `a[*1:2] |-> strong(c ##[1:$] b)`). The cases also pass point 1 (finite rows) through `compile_monitors`.
58. **Exhaustive lassos.** For `s_eventually b`, `a |-> s_eventually b`, `a |=> s_eventually b`, `s_eventually [2:$] b`, `a s_until b`, `a s_until_with b`, `strong(a ##[1:$] b)`, `a |-> strong(##[1:$] b)`, `strong(b[->2])`, `always (a |-> s_eventually b)`, `disable iff (a) s_eventually b`, `a |-> s_eventually $past(b)`, every lasso of the signals `a`, `b` with 1 to 3 written samples and every loop index gives the verdicts of point 57 (a fast representative subset in the default run, the full set under `slow`). The properties are built through the front end (Slang) from SystemVerilog text.
59. **Mutants are caught** (each a test that a deliberately wrong variant fails): a witness that ignores `disable iff` (`disable iff (d) a |-> strong(##[1:$] b)`, `b` never, `d` recurring: no attempt is FALSE, so liveness must pass); a witness that re-picks in the sample it is freed (`a |-> strong(##[1:$] b)` with `a = b = 1` at every sample: WITNESS kind, every obligation ends one sample after its launch, liveness must pass); the pending bit used outside its class (the same property and trace: the configuration machine's `live` is non-empty after every sample although no obligation stays pending for ever, which is why the machine is WITNESS).
60. **No false never-fails warning.** `never_fails_warning` gives no warning for a part with a liveness kind (it can still fail its liveness check); weak parts keep it.

**`not` of an unbounded sequence (`docs/semantics.md` §9.6).** `not S` for an unbounded sequence `S` is decided by a **negated configuration machine** (`ConfigMachine.negated`): the configurations and the step are those of `S`, only the events swap. One obligation of `S` matches, dies (frontier empty without a match) or stays pending for ever (16.12.2, 16.12.3): `not weak(S)` (default strength, `weak(...)`, weak `until` / `until_with`) is FALSE at the first match, TRUE at death and FALSE when the obligation stays pending for ever (a strong property: safety part plus liveness part); `not strong(S)` (`strong(...)`, `s_until`, `s_until_with`, `s_eventually`) is FALSE at the first match, TRUE at death and TRUE when pending for ever (a weak property: safety only; `not s_eventually b` is `always !b`).

61. **Negated kind.** `ConfigMachine.negated` is `True` exactly when the consequent is `not S` (also under `|->`, `|=>`, `always`), `False` otherwise. The number of configurations is that of `S` (hand-derived counts: `not (a until b)` 1, `not (a ##[1:$] b)` 2, `not s_eventually [2:$] b` 3). `liveness` follows the strength after negation, for an `assert`: `not weak(S)` has `PENDING` with at most one configuration and `WITNESS` otherwise, `not strong(S)` has `None`. A `cover` of `not S` with an unbounded part stays rejected (4d rule, unchanged message).
62. **Acceptance.** For an `assert`, `not S` is accepted in exactly the positions `S` itself is (point 54: the whole property, the consequent of `|->` / `|=>` with any accepted antecedent, `always`, `always [m:$]`, `nexttime`, bounded `always`, property `if`). For an `assume`, `not strong(S)` (and `not s_until`, `not s_eventually`) is accepted (weak, safety only) and `not weak(S)` is strong: accepted with one configuration (`not (a until b)`, point 69) and rejected by the compiler otherwise (`not (a ##[1:$] b)`, point 70). `not` of an unbounded weak `eventually`, or of `s_eventually` with a property or unbounded operand, keeps its message.
63. **Events.** For a negated machine the events of `configuration_step` are those of the unnegated machine of the same `S` with `failure` and `success` swapped: `failure` where an obligation of `S` matches, `success` where a frontier dies. `disabled` and `triggered` are unchanged. When the consequent automaton has no configuration (`not strong((a ##[1:$] b) intersect c)` and `not ((a ##[1:$] b) intersect c)`: the operands never end together), the trigger-time path of 4a applies swapped: `success` at the trigger, never `failure`, never busy, and for the weak form the liveness check passes.
64. **Verdict against the reference, table cases.** The cases of `not_liveness.trace` and the promoted not-of-unbounded cases of `lasso.trace`, `unbounded.trace`, `until.trace` and `liveness.trace` (they lose `support: oracle`) run through every layer. For the cases with a liveness kind, point 57 holds unchanged (the liveness part of `not weak(S)` is the 5a one). For `not strong(S)` (no liveness part): no attempt is FALSE only in the limit (`inf-outcome` `F` always has an `inf-decided` sample), and the machine reports a failure exactly when some attempt is FALSE at a finite sample, at or before the earliest. The review case `a[*1:2] |-> not (c ##[1:$] b)` (attempt 0 FALSE at sample 1 while the obligation of the second trigger stays pending for ever) has a finite failure and a failing liveness signal, not compared.
65. **Exhaustive lassos.** Every lasso of the signals `a`, `b` with 1 to 3 written samples and every loop index (a fast subset in the default run, the full set under `slow`) gives the verdict of point 57 for `not (a until b)`, `not (a until_with b)`, `not (a ##[1:$] b)`, `not weak(a ##[1:$] b)`, `a |-> not (b ##[1:$] a)`, `a |=> not (##[1:$] b)`, `not (b[->2])`, `always (a |-> not (b ##[1:$] a))`, and with `disable iff`; and the safety rule of point 64 for `not strong(a ##[1:$] b)`, `not (a s_until b)`, `not (a s_until_with b)`, `not s_eventually b`, `a |-> not strong(b[->2])`, `always (a |-> not s_eventually b)`, and with `disable iff`.
66. **Finite-trace differential.** The differential comparisons of the configuration machine against the reference on every prefix (points 21, 22: failures, successes and "some obligation is live") include `not` of an unbounded sequence of every strength (generated, and the fixed properties `not (a ##[1:$] b)`, `not strong(a ##[1:$] b)`, `a |-> not (b[*1:$] ##1 c)`, `a |=> not strong(b[->2])`, `always (a |-> not (b ##[1:$] c))`, `a |-> not ((b ##[1:$] c) intersect d)`).
67. **Mutants are caught** (each a test that a deliberately wrong variant fails): the negation ignored (events not swapped: `not (a ##[1:$] b)` with `a = b = 1` for ever passes, and with `a = b = 0` for ever fails); no liveness part for `not weak(S)` (`not (a until b)` with `a = 1`, `b = 0` for ever passes); a liveness part for `not strong(S)` (`not strong(a ##[1:$] b)` with `a = 1`, `b = 0` for ever fails); `never_fails` ignoring the negation (point 68).
68. **Never-fails.** `never_fails` is `False` for a negated machine (it fails on a match): no warning for `not strong(1 ##[1:$] b)` although its frontier cannot die. The soundness oracle (points 49, 50) covers negated machines; the criterion of the unnegated machine is caught as a mutant.

## Strong `assume` in the one-configuration class (`docs/semantics.md` §9.6)

An assumption restricts the traces to those on which the property holds (16.14.2). A strong part (strong after negation, `passes.validate.strong_unbounded_part`) of an `assume` whose configuration machine has at most one configuration (L1: `a |-> s_eventually b`, `s_eventually b`, `always (a |-> s_eventually b)`, `a s_until b`, `not (a until b)`) is accepted: its safety part is the configuration machine's `fail` (unchanged), its liveness part the pending bit, emitted as a fairness constraint `s_eventually !busy` (the monitor, point 19 of `generated_monitors`). An L2 part (a witness: several configurations) is rejected, because a witness picks one obligation and as an assumption would constrain only the obligation the solver chooses (a weaker assumption). On a lasso, "the assumption admits the trace" means that the configuration machine reports no failure on it **and** `support.simulate.liveness_fails` is false.

69. **Liveness kind of an `assume`.** `ConfigMachine.liveness` is `Liveness.PENDING` for an `assume` whose strong part has at most one configuration (hand-derived counts, as for points 52 and 61: `s_eventually b`, `a |-> s_eventually b`, `a |=> s_eventually b`, `always (a |-> s_eventually b)`, `a s_until b`, `a s_until_with b`, `not (a until b)`, `not (a until_with b)`: one each), the kind of the `assert` of the same property. A weak `assume` and `not strong(S)` keep `None`. `passes.validate.validation_problems` no longer reports a strong `assume` part (it gives the same problems as for the `assert` of the property, with `shapes` on and off, in every position of point 54).
70. **Rejection of the L2 class, by the compiler.** `compile_monitors` (and `compile_configuration_machine`) raise `CompileError` for an `assume` whose strong part would need `Liveness.WITNESS` (`a |-> strong(##[1:$] b)` 2 configurations, `strong(a ##[1:$] b)` 2, `s_eventually [2:$] b` 3, `strong(b[->2])` 3, `not (a ##[1:$] b)` 2, `a[*1:2] |-> strong(c ##[1:$] b)` 2); the message contains `a strong unbounded property (liveness) in 'assume'` and says why (a witness picks one obligation). The same properties are accepted for an `assert` with `WITNESS`.
71. **Verdict against the reference, table cases.** The cases of `fairness.trace` (hand-derived, `kind: assume`, all lassos of the L1 class: `s_eventually`, `a |-> s_eventually b` answered and unanswered, `always (a |-> s_eventually b)`, `s_until`, `not (a until b)` dying, matching and pending for ever, `disable iff` recurring and a single pulse, a `$past` antecedent at the first sample) run through every layer; each has a liveness part, and the assumption admits the lasso (the exactness claim above) exactly when no attempt of `lasso_attempt_results` is FALSE, at a finite sample or in the limit, and exactly when the table's `inf-outcome` row has no `F`. Their finite rows also pass point 1.
72. **Exhaustive lassos.** For `s_eventually b`, `a |-> s_eventually b`, `a |=> s_eventually b`, `a s_until b`, `a s_until_with b`, `always (a |-> s_eventually b)`, `not (a until b)`, `not (a until_with b)`, `$past(a) |-> s_eventually b`, `a |-> s_eventually $past(b)`, and with `disable iff`, every lasso of the signals `a`, `b` with 1 to 3 written samples and every loop index (a fast subset in the default run, the full set under `slow`): the assumption admits the lasso exactly when no attempt of the reference is FALSE (at a finite sample or in the limit).
73. **Mutants are caught.** The fairness part missing (`assume a |-> s_eventually b` admitting the lasso `a = 1`, `b = 0` for ever; also `assume not (a until b)` admitting `a = 1`, `b = 0` for ever): the exactness test fails; the safety part is that of the `assert` (a match of `not (a until b)` fails, a pending obligation does not).
74. **Boundary cases** (hand-derived). `disable iff (d) a |-> s_eventually b` with `a = 1`, `b = 0` for ever: `d` at every second sample is admitted (each obligation is aborted by the next `d`, 16.15); a single `d` at sample 0 is not admitted (the obligations launched after it stay pending for ever). `$past(a) |-> s_eventually b` with `a = b = 0` for ever is admitted (no trigger at the first sample, 16.9.3, nor later), with `a = 1` for ever and `b = 0` not admitted. `assume property (s_eventually ($past(a) || b))` stays rejected by the first-sample rule, as the `assert` is: validation runs on strong `assume` parts after the liveness rejection moved to the compiler.
75. **Never-fails hint.** `never_fails_warning` of a weak `assume` that cannot fail ends with `(a fairness constraint needs a strong assume, see docs/usage.md)` (it used to say that a strong assume is not supported yet); the `assert` hint is unchanged (`tests/unit_tests/test_configurations.py`).


**Shared resource guards.**

76. Every public compiler entry, including `compile_directive`, `compile_monitor`, `compile_monitors`, `compile_attempt_machine`, `build_attempt_machine` and `compile_configuration_machine`, checks the written property before validation, lowering, range expansion or dispatch. Saturating structural preflight rejects huge bounded ranges without enumerating them. Mandatory prefixes of unbounded ranges are checked without replacing `$` with a finite limit. Existing attempt/configuration budgets remain enforced.
77. Construction accounts incrementally for created letters and graph/netlist work, including intermediate or folded-away work, before allocating it. Canonical temporal state is checked by reachable positions, without a dense state estimate rejecting a compact plan. Exhaustion reports the resource and its limit through a CompileError at compiler boundaries (BudgetError for the low-level attempt builder). A configured small limit admits its boundary and rejects the next charge; counters saturate and never wrap.
78. Limits apply per monitor compilation, with an additional written-directive preflight before conjunction splitting. Expression widths and distinct sampled-history expansion are checked too. Work is charged before structural hashing of sampled operands; recursive written-estimate capacity failures become resource diagnostics. They are compiler resource policy, not a total-run memory limit or a solver-runtime guarantee. Accepted monitors preserve all existing event semantics and generated bytes.

79. **Cached incoming edges.** Each automaton retains deterministic ascending predecessor lists, including loops and accepting continuations. Per-attempt successor construction and shared emitted frontiers visit these edges rather than scanning all source letters for every target. Accounting follows the new O(V + E) visits per full frontier evaluation; no obsolete quadratic charge rejects an otherwise admissible monitor. Event semantics, letter numbering and generated bytes remain unchanged for previously admitted monitors.

80. **Reverse dead-state discovery.** After finding start-reachable positions,
    construction walks reverse edges from reachable accepting positions to find live
    positions in O(V + E), replacing repeated fixed-point scans. It prunes only
    structural dead states, retains constant-false guards, handles cycles, preserves
    creation-order numbering, and charges the actual index/queue traversal. Previously
    admitted machines keep identical events and generated bytes.

81. **Bounded delay membership.** Contiguous positive delays are tested and
    their endpoints obtained in constant time, without materializing/searching a delay
    list. Construction still creates every required filler position. Zero-delay
    fusion, nullable operands, end samples and deterministic numbering are unchanged;
    accounting charges the constant-time probes actually performed.

82. **Sparse per-age construction.** Cache guard-independent reachable
    positions and successor edge groups lazily for each automaton/local age. After
    first-use initialization, evaluate only potentially active positions, retaining
    accepting continuations and preserving distinct attempts, overlap, earliest
    decisions, nonvacuity and events after failures. Charge planning/current-run
    unavoidable visits before cache/gate allocation; do not use removed dense work or
    predict exact folded gates with another compiler. Preserve existing netlist
    creation order where possible and check complete before/after output dumps.

**`initial.trace`.** Its `scope: attempt` cases (`procedure: initial`, hand-derived: the enabling condition `FirstSample` leaves one attempt) are run by the per-attempt layer like the other attempt tables (point 71's list of files), and its default-scope cases by the canonical machine (the machine evaluates `FirstSample` as 1 at sample 0 only).

**`composition.trace`.** Its one `scope: attempt` case, `intersect_of_goto_2_and_goto_3_never_matches` (from EBMC's regression `pending_intersect1`, hand-derived: an unbounded consequent, so attempt scope), is run by the per-attempt layer with the other attempt tables (point 71's list of files).

**Scheduling.** The default tier retains trace fixtures, focused counterexamples and small never-fails soundness parts. Broader short-trace enumerations, anchored cross-products and generated never-fails searches use `extended`; their original assertions, trace limits and example counts are unchanged. Existing larger searches remain `slow`. `--extended` includes default, and `--slow` includes both.

Generated property searches and larger mutation searches are `extended`; hand-derived fixture regressions remain in default. The tier split changes scheduling only, not search sizes, assertions or the trace expectations.
